# 开源项目语气

---

## 这个项目是什么

明思是一个个人思维训练系统。

它不是一个商业化 SaaS 产品，不是一个"用 AI 做 XX"的技术演示，不是一个追求用户量增长的创业项目。

它是一个开发者给自己做的工具——用来解决一个真实的问题：每天做了很多事，但没想清楚。

之所以开源，是因为这个问题可能不只是我一个人的。如果你也有类似的困扰，欢迎看看这个思路对不对，代码写得行不行，功能设计合不合理。

---

## 欢迎的贡献方向

### 核心逻辑改进
- 思考卡片的分类算法和 Prompt 优化
- 追问逻辑的深度和引导质量
- 透镜框架的设计和实现
- 判断校准的计算逻辑

### 用户体验
- 输入流程的降低摩擦（语音分段、快捷短语、模板引导）
- 卡片确认交互的效率优化
- 信息密度的平衡（太密看不过来，太疏浪费时间）
- 历史证据的浏览和检索体验

### 新透镜设计
- 第一性原理透镜
- 苏格拉底式提问透镜
- 反脆弱透镜
- 查理芒格多元思维模型透镜
- 其他有实际价值的思考框架

### 技术改进
- 本地数据的性能优化
- SwiftData 的最佳实践
- AI 响应的流式处理和错误恢复
- 可测试性改进

### 文档和例子
- 复盘方法的说明文档
- 使用案例（脱敏后的真实复盘流程）
- 英文文档翻译

## 不欢迎的方向

### 不要把它变成日记 App
明思的输入是为了训练判断，不是为了记录生活。如果你想做"漂亮的日记模板"或"心情追踪"，这不是合适的项目。

### 不要把它变成 Todo App
明思的任务是从判断中推导出来的可验证命题，不是通用任务管理。如果你想做甘特图、协作任务、截止日期提醒，请用其他工具。

### 不要把它变成 AI 聊天机器人
AI 在明思中的角色是整理和追问，不是对话和陪伴。如果你想做"AI 朋友"或"智能助手"，这不是这个项目的方向。

### 不要做游戏化机制
不要连续打卡天数、不要积分排行榜、不要成就徽章、不要"你比 80% 用户更自律"。这些机制短期有效但长期有害，而且和产品的核心理念相悖。

### 不要做社交功能
复盘是个人行为。如果你想做"好友动态""分享到朋友圈""互相监督"，这不是这个项目的方向。Lens Pack 的分享是透镜框架的分享，不是复盘内容的分享。

### 不要做数据采集
不要加埋点统计、不要加用户行为追踪、不要加任何把用户数据发送到第三方服务器的功能。隐私原则是不可谈判的。

### 不要做商业化的提前布局
不要在代码里预留广告位、不要做付费墙的框架、不要收集用户信息以备将来变现。这个项目现在不是一个商业项目。

## 怎么参与

1. Fork 仓库
2. 创建功能分支（`feat/xxx` 或 `lens/xxx`）
3. 提交 Pull Request，描述清楚你改了什么、为什么改
4. 如果是大的功能变更，建议先开 Issue 讨论

---

## 关于 API Key

明思需要用户自行配置 AI 服务的 API Key。这是刻意的设计决定：

- 用户的思考数据只发送到用户自己选择的服务
- 项目维护者不承担 API 费用和合规责任
- 用户可以选择任何兼容 OpenAI API 的服务

请不要提交包含 API Key 的代码。请确保你的 PR 中没有硬编码的密钥或 token。
