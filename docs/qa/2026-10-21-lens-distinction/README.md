# 换位理解：从证据核对到理解双方侧重点

日期：2026-10-21。承接[透镜目录](../2026-10-21-lens-library/README.md)的实际语义不足，不扩大为全 App 或长期能力验收。

## 最大问题与本次修正

本次审视发现一个具体的引导质量问题：方法名称不同，底层仍容易统一要求补证据。旧换位理解的目的与问题策略主要要求区分原话和动机猜测；generateQuestions 总规则同时要求每个问题来自实际证据缺口或反证，本地门又靠“缺、证据、约束”等词判断是否有思考材料。用户已经区分事实与猜测时，仍会被要求再做同样核对，难以练习准确表述另一方诉求的能力。

- 目录升级 builtin.v3，保留十个持久化 id、现有 reasoning move 和 schema。换位理解的说明、示例、目的与策略改为准确表述双方已知诉求和限制，比较侧重点；没有表达过的动机继续未知，不补造善意故事，不要求新谈话或原谅伤害。
- generateQuestions **1.28.0 / schema 6**，回退 **1.27.0**。真实取舍、用户价值和双方已知侧重点本身可以支持有用问题，无事实缺失时使用 none。继续允许零或一个问题、拒绝和停止，不制造作业。
- diagnoseTrainingCase **1.3.0 / schema 2** 读取新目录；回退 **1.2.0** 的完整 v2 目录已冻结，避免历史模板因读取当前目录而漂移。旧 v2 上下文缺 packVersion 时仍按自身版本恢复，不被标成 v3。
- 本地质量门对无缺口的替代解释/前提重看使用结构校验：完整用途、来源和具体判断对象；保留来源是否属于当前确认卡片的独立校验。它只判断能否接纳，不声称能从标签证明语义有效。

第一轮实际问题为：

> 你希望按期展示工作，他提到本周只有两人值班并请求延后一周；只根据这些已知表达，你会怎样描述双方侧重点的差别？
