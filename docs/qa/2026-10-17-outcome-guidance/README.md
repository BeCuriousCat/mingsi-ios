# 验证行动、结果校准与原则候选 · 2026-10-17

继续审视“帮助被变成训练流程”的问题。本轮实际执行此前未验的行动设计、结果校准及原则候选生产服务；所有材料为合成材料，复用已授权的 CC Switch 当前伊莉丝 Responses 连接，仅使用固定 iPhone 17 / iOS 26.5 模拟器。

## 已复现的问题

首次真实执行在第二次请求后失败。模型已经正确指出：用户选了已完成、高价值和判断已确认，但未提供朋友是否完成、网络是否正常、卡点或任何反馈；因此验收条件无法核验、判断仍待验证，并且没有生成成长证据。客户端仍抛出 weakVerificationCalibrationNote 和 weakVerificationRecommendation。

旧本地门要求同时出现六组固定表达，包括“原判断”“实际证据”“证据收获”“判断更新”“可观察证据”“完成标准”。这迫使一段自然的简短反馈重复命名同一内容；真正有据的输出会被当成无效，用户看不到。推荐虽提出可自愿记录一个比较信号，也因缺少“下一步”等指定词被拦。

[首次摘要](evidence/initial-live-summary.json)及[完整附件](evidence/initial-live/manifest.json)保留失败，只有前两次实际请求，不计为四场景通过。没有根据测试红灯认定模型语义不合格。

## 修复

第一次尝试只减少必需标签并增加自然措辞，专项 250 项通过；再次真实调用仍因换一种自然表达而被拦。第二份模型正文把目标判断直接引用后说明“仍应保持开放”，并正确保留未知，见[第二次失败摘要](evidence/prose-live-summary.json)及[附件](evidence/prose-live/manifest.json)。这证明继续补关键词不可靠，不能把首次绿灯视为最终修复。

最终改为结构化状态与用户文案分开：

- verifyQuest 1.10.0 使用 output schema 4，保留 1.9.0 原文/回退（已与首次真实请求逐字比对）。返回独立的 calibration_assessment：证据 observed/missing/conflicting、验收 met/not_met/not_assessable、判断 supported/weakened/unresolved，以及证据原文片段。
- 当前服务强制检查 assessment 存在、枚举合法、引用数量/唯一性及逐字属于本轮结果原文。有观察时必须至少一段原文、至多三段；没有结果时必须无片段、验收不可判断、判断未决，并且没有成长证据。缺字段或状态冲突均失败，不回退伪造反馈。
- 当前页面文案只做最小长度检查，不再要求六组固定标签。两三句反馈说明结果、验收边界和判断更新；下一次自愿观察只放 recommendation，不重复在正文里。旧响应可解码回放，旧文本门仅作兼容。
- 真实旧回复作为用户文案回归；另覆盖短句反馈、缺失状态、缺结果却确认、虚构/重复/空引用、无结果却生成成长等边界。引文的字面归属可验证，含义及判断仍需内容复核，不能靠结构宣称语义成立。
- live 新增 --outcome-guidance，最多四次连续请求：单行动、无观察的正面自评、一次好结果不提原则、独立重复事例及明确边界允许候选。请求附件补齐完整结构化 context_payload 和来源 ID；响应为适配器归一信封，未保存原始 SSE，也不是线上请求字节留档。

## 当前验证

完整单元回归最终 1374 通过、0 失败、6 项显式 opt-in 跳过，见[摘要](evidence/final-unit-summary.json)，`/tmp/mingsi-outcome-final-unit-20261017.xcresult`。跳过项为需单独启用的外部调用/导入；本轮四场景真实验收另行执行。脚本契约检查与 Python 编译通过。没有修改 UI，本轮没有新增 UI 验收。

最终伊莉丝真实四场景：一条 opt-in 测试通过、0 失败、0 跳过，见[执行摘要](evidence/final-live-summary.json)、[逐条 AI 内容复核](evidence/final-live/semantic-review.json)及[请求/响应](evidence/final-live/manifest.json)，`/tmp/mingsi-outcome-structured-live-20261017.xcresult`。确认单行动有区分性信号、正面自评不等于观察、单次好结果返回 null、明确边界和独立实例可保留候选。实际结果校准正文两句，未因自然措辞再被拦截。原则候选保留“仍需验证”和例外，不确认因果。

三次 live 共八次回应：前两次各只有两次请求，最终四次完整通过。仅认可这些合成样本，不宣称稳定成功率或全链路完成。有观察时的引文归属和冲突状态本轮只做本地回归，没有真实模型正向样本。行动的回看问题仍包含同一判断的三个条件分支，实际页面负担待验证。


保留开发中失败：首轮专项 248 通过、2 失败，原因是升级断言误改了 generateQuests、遗漏 verifyQuest 对应断言；已纠正，两者实际版本各自保留。结构化首轮完整回归为 1373 通过、1 失败、6 跳过，发现最小长度允许了一条旧泛泛文案；调整后上述最终回归通过。最初新增合成卡片使用不存在的 judgment 类型，已改为现有 decision 后构建。
