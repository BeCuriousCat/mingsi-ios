# 共享语音输入验收 · 2026-10-03

## 交互

每个自然语言输入框使用同一个 `PushToTalkInput` 组件。右下角保留 44pt 圆形按钮，文字区域为按钮预留空间。

| 状态 | 图标 | 点按行为 |
| --- | --- | --- |
| 待输入 | 麦克风 | 开始语音输入并收起键盘 |
| 权限／启动准备 | 叉号 | 取消准备 |
| 正在录音 | 停止方块 | 停止录音并等待最终识别 |
| 等待最终识别 | 叉号 | 取消本次识别 |
| 完成／中断／失败待审核 | 循环箭头 | 清除本次识别并立即重新录音 |

识别结果可以编辑；“添加到输入框”只追加到当前原文，不直接提交业务操作。“丢弃本次识别”保留原文。

`SpeechInputController` 同步接收服务状态，移除原来依赖 SwiftUI `onChange` 和 40ms 延时的复录逻辑。取消后的旧权限与识别回调由服务的 generation 校验隔离。今日闪念、导师交流／反馈／理解编辑、复盘、项目和原则等自然语言输入复用此组件；技术设置字段沿用其专用输入控件。

## 后续修订与复验：输入框内键盘入口、独立控件语义

首次自动聚焦时，SwiftUI keyboard toolbar 可能不挂载。共享组件改为在输入框右下角、麦克风左侧显示 44pt 的收起键盘图标，主输入及识别校对输入聚焦时均可使用。移除原键盘工具栏，避免双入口；按钮只改变焦点，保留所有文字。两个图标之间保持 8pt 间距，输入文字为控件预留空间。

实际 UI 回归发现交流页外层 accessibilityLabel 会把麦克风和键盘按钮都覆盖为“你想说的话”。组件现在保留独立子控件语义，交流／理解编辑不再覆盖整组的按钮名称；页面通过普通 State 传递焦点请求，实际 FocusState 由组件拥有。理解、旧版输入和答题输入的 automation ID 直接传给组件内的编辑器。

## 补充验收：多个输入框切换录音

继续复核发现，每个组件独立持有录音服务，多个输入框可能争用同一个设备麦克风。`SpeechInputController` 现在通过主线程上的弱引用统一协调麦克风：开始新输入框的录音前，取消旧服务并隔离其迟到回调。旧输入框已经识别的部分保留在待确认区，不自动写入正文；权限准备中的旧输入直接取消。非当前输入框的确认或丢弃操作不会取消当前录音。

源码扫描确认 37 处 `PushToTalkInput` 调用，覆盖闪念、交流、反馈、理解编辑、复盘、答题、项目、原则等输入。API Key、URL、模型名等专用设置字段仍使用其原输入控件。入口为输入框右下角的小图标；开始、停止、取消收尾、完成或中断后复录均通过同一位置操作。
