# 首页导师：选择标准与有界等待

日期：2026-10-21。延续[透镜方法库](../../lens-library-design.md)，本次修正首页「交流一件事」实际使用的导师提示词，而不是把 Today 透镜与教材入口混为一体。

## 实际问题与修改

旧首页导师合同要求建议首段必须给出首选，即使用户尚未表达优先级。这可能让模型擅自替用户排列收入、效率、休息与关系。`mentorRespond` 现为 **2.13.0 / schema 1**，系统策略 `mentor.system.2.13.0`、评估套件 `mentor.m1.2.13.0`；2.12.0 原文冻结并可回退。`mentorDraftUnderstanding` 仍为 2.6.0。

当前标准足够时直接推荐并说明依据；标准未知时只解释一个条件式取舍，尊重不补问、不加任务。价值偏好是用户的选择标准，不是待证明的事实缺陷。事件报告、动机解释、自我标签分别对待；一般原理和条件示例无需先提交个人经历。用户补充或改变优先级后按新标准更新建议，不把满意、采纳或完成练习写成能力提升证据。没有新增输出字段、本地关键词分流或数据库迁移。

首次在线验证约 32 秒后没有可呈现回应。源码核对发现导师执行器、页面看门狗和验收 HTTP 配置都设置 30 秒截止；原附件没有底层错误码，**不能断言该次失败一定由某层截止造成**。现在 Responses 连接采用最长 120 秒的总预算，普通 API 维持 30 秒；十秒出现等待提示，用户可立即取消。120 秒是明确的工程上限，不是供应商延迟保证。

App 初次组装与设置刷新均传入相应策略。每次请求固定捕获策略、transport 和 Prompt；页面看门狗与执行器共用开始时刻，准备时间计入预算。正常回应和「整理理解」都使用同一策略。过期或取消后迟到回复仍被拒绝；一次 HTTP 尝试、无自动重试、无格式回退不变。超时文案不再硬写 30 秒。验收 harness 同步 HTTP 预算并记录安全的错误类型、domain/code、耗时与是否有正文，不记录凭据或错误正文。

## 真实连接：两轮承接与语义审读

在已授权的当前 CC Switch 伊莉丝 HTTPS Responses 连接上，以新预算显式执行一次双轮复验，**1 通过、0 失败、0 跳过**，见[摘要](evidence/live-budget-summary.json)，原结果 `/tmp/mingsi-mentor-budget-live-20261021.xcresult`。两轮为不同用户输入，无自动重试；首轮成功后确认回执，通过新 repository/store 重开同一 SQLite 文件，再发第二轮。恢复没有请求模型，最终时间线为两条用户输入、两条 assistant。

Codex AI 已逐篇阅读两条真实 assistant 正文，见[语义审读与正文索引](evidence/live-semantic-review.json)：

- 首轮约 **8.03 秒**：用户尚未排序兼职三百元和陪父母，模型比较一个条件式取舍，没有替用户决定、追问或安排任务。首轮仍略长，“无法兼顾”作为条件表达，而非已证实的安排事实。
- 第二轮约 **19.95 秒**：用户补充房租已留够、两周内无其他相聚机会，并明确相聚优先；模型按这些新标准建议这次不接兼职去聚餐，保留放弃三百元的代价与本次边界，没有扩张为永远关系优先。

**两次成功均短于旧 30 秒截止，因此不能归因于延长预算，更不能据此证明原失败一定是超时。** 它们证明此次生产 store/transport/解析/真实 SQLite 承接，以及这个合成场景下的条件比较和建议更新。输出文件是保留 assistant 文本的适配后 envelope，不是原始 SSE；模型别名不是上游身份或计费证明。本次用 headless 回执，不是网络 UI 验收；更不是个人真实使用或长期能力提升。
