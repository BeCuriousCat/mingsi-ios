# 当下帮助请求优先：疲惫与表达示范

2026-10-21。上轮属于 progress：完成显式材料选择、真实模型验证、UI 首尾阅读和点击区域修复并恢复正常 App。本轮从当前源文件重新审视剩余提示词冲突，不重复已成功的付费请求。

## 最大问题与本轮发现

明思最大的产品问题是训练规则仍可能压过当下需要。之前已经修正强制行动、视角同质化、已有标准却不建议、直接解释没有内容及旧片段替代本轮诉求；这次实际检查当前 2.16.0 模板，仍发现两个源文本矛盾：

1. 前文说疲惫不等于拒绝帮助，后文仍写“倾听、疲惫、拒绝、想结束时 question=null”。用户很累但主动希望用一个问题厘清标准时，会收到互相冲突的规则。
2. 前文允许按请求示范表达，后文却一律禁止 body 问号。用户要一句向第三方询问的措辞时，系统把示范问句与追加用户追问混在一起。当前生产质量门本来允许引号内问句，Prompt 比客户端合同更严。

这些是已确认的资产冲突，不声称它们在每次实际调用都会导致失败。修改前合同回归 **0 通过 / 1 失败**，见[基线](evidence/baseline-summary.json)。

## 修改

mentorRespond **2.17.0 / schema 1**，完整冻结 2.16.0 回退。疲惫不单独取消用户请求的问题；仍须有实质价值、遵守原提问预算和明确停止边界。引用原话或按请求示范给第三方的问句可在引号内保留问号，示范不是发生的事实、用户承诺或必做任务；不得把向用户补材料的追问包进引号规避限制。无新字段或路由关键词。入口文案同步从“训练深度”改为“思考方式”，Deep 明确改变审视角度而非问题数量；输入参考明确可选、不必逐项填写，不要求用户先给问题分类或备好问题。

原质量门保持：引号外追加追问仍拒绝。补充回归同时验证可选问句示范和正文多出追问的拒绝，保留过去其他质量规则。
