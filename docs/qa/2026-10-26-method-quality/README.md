## 评审规则（在请求之前登记）

每个场景按四项各0–2分评估：贴合当前请求、具体有用、事实与边界、低负担。2表示满足目标；1表示有帮助但有可指明缺点；0表示失败。场景通过要求总分至少7/8且无0分；条件变更的两个回合均需通过。

放行仅代表限定试用，必须同时满足：

1. 来源和编辑范围充分支持当前有限主张，不能冒称全书提炼。
2. 六类至少五类通过，停止、缺事实和条件变更三类必须全部通过。
3. 至少一个同场景正向比较具有可指明的增益。平局、仅更长、更像框架或更会引用作者，均不算增益。基线已经做得好的情况如实判平局。
4. 无关键失败：虚构事实/承诺/来源、越过停止意愿、忽视硬约束、把方法来源当成用户证据、未执行当前请求、不可解析或请求/保存未完成。
5. 实际内容哈希、Prompt版本和评测报告绑定。内容或Prompt变化使旧放行失效。

评分与对照由Codex AI编辑完成，并保存实际回答和逐项理由。AI判断不是独立盲评；一次合成样本的结果不能外推长期效果、用户喜欢程度或稳定成功率。

## 无效时的处理

- 没有增益：保持待验证，优先合并进现有透镜，不靠增添标题扩充目录。
- 有帮助但负担大：缩短方法，只保留影响回答的动作；新内容需要新批次，不覆盖本次失败。
- 来源不够：补实际原文与证据映射，暂作资料，不能自动启用。
- 忽视停止/编造/未更新：立即阻止试用；先修具体原因再登记新批次。
- 后续用户反馈“没帮助/不相关”与具体理由是输入，不能直接当作能力退步或人格标签。用真实用户的可发送产物、选择是否更清楚、后续结果检查真实价值；未收到此证据不宣称能力提升。
