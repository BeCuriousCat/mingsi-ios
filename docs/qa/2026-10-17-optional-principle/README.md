# 验证行动保存与可选原则整理 · 2026-10-17

当前最大问题的一处具体表现是：用户只想保存一个待验证行动，系统却自动请求原则候选，增加等待、失败入口和产出压力。候选往往又应当为空，用户仍要经过一页才能结束。

## 改变

行动确认页主操作改为“保存验证，今天先到这里”，成功后直接完成回顾，vNext 返回今日事项；不调用原则生成。次要入口“保存并整理原则候选”保留生成能力，只有用户主动选择才请求。候选仍可编辑、保存、跳过。此前覆盖原则流程的测试改为走明确次操作，默认结束另有独立回归。

先写入行动与完成记录，再安排提醒和离开页面。写入失败保留当前页、行动及原问题，允许同 ID 重试；保存中禁用重复提交、重置、前后导航和切换事项。事项状态只在写入成功后更新内存。既有可选原则完成路径也不再忽略事项保存/状态失败就清空页面。

写入使用现有多个仓储，没有新增跨仓储事务；中途失败可能已写入部分数据，但不显示完成或丢弃当前输入，重试使用相同业务 ID。崩溃时的跨仓储一致性本轮未证实，不把保存门等同于原子事务。

## 验证

固定 iPhone 17 / iOS 26.5：专项 525 通过、0 失败，最终完整套件 1378 通过、0 失败、6 个显式 opt-in 跳过。见[专项](evidence/focused-summary.json)与[完整摘要](evidence/full-unit-summary.json)。最终完整套件增加 session、case status、daily entry 三个最终写入点的真实 SQLite trigger 故障和重试；默认路径零原则请求、显式次操作恰好一请求、重复点击/保存期间返回保护也有回归。

首轮三条 UI 均失败，实际层级停在“正在恢复交流”，没有进入目标页面。旧视觉启动方式使用了正式恢复路径；已添加显式 --today-loop-ui-fixture，使用无持久化仓储、无 Keychain 刷新及 MockLLMClient 的隔离 Today 夹具， root 和实际最大字号覆盖仅在显式 DEBUG 参数启用。未清除实际连接或用户数据。首次失败[摘要](evidence/initial-ui-summary.json)保留；夹具编译曾有测试构造参数顺序错误，已修正。

隔离夹具首轮为 2 通过、1 失败：[摘要](evidence/isolated-ui-summary.json)。默认完整流程和主动候选入口已通过；最大字号下，入口位于长内容末尾，超过有限滚动范围。已将次操作移至固定主按钮下方，使其直接可见；本次作一次最终显示和操作确认，不继续可选视觉调整。最终三条 UI 全部通过、0 失败、0 跳过，见[最终摘要](evidence/final-ui-summary.json)及[截图清单](evidence/screenshots/manifest.json)。已人工查看正常与实际最大辅助字号两张截图：主操作和次操作均可见且可点击，默认直接结束与显式整理候选两条路径通过。两张实际截图均为深色；附件名中的 light 不代表浅色验收。最大字号下固定操作区占据较多屏幕，页面阅读空间仍有限，本轮不将操作可达等同于整体易用性通过。本轮无额外外部模型请求，未发布安装包。

## 限制

不代表整个 App 完成。真实手机、真实个人场景和日常使用尚未验证；可选原则页本身的确认/保存语义及跨仓储崩溃恢复仍需审查。Prompt 内容沿用上一轮真实调用验收，不因流程修改宣称模型效果提升。
