# 单条闪念进入交流验收 · 2026-10-03

## 路径与数据边界

在今日闪念的每条已保存记录下点击“聊聊这条闪念”，关闭闪念页后打开交流页。单条记录即可进入，不要求先聚合；尚有未保存输入时先要求保存。点击该入口只进行本地写入，不调用模型，也不要求先配置 Key。进入后再点击“聊聊这条闪念”或补充文字并发送，才发起在线交流。

仓储通过一次 SQLite 事务创建会话、用户原文快照和指向 capture ID 的来源链接。来源缺失、空白或任一步写入失败都不留下半个会话；同一 session ID 重放幂等，另一条闪念不能冒用。来源详情从这次交流保存的快照读取并校验 hash，拒绝外会话、缺失链接及 hash 不符的来源。

模型收到所选原文的 timeline item 引用，其 SourceLink 回链至原闪念；没有重复追加同一份材料。原闪念正文、状态和时间不被改写；结束、删除交流及历史恢复不删除原闪念。来源查看随历史恢复保持可用。

## 实际验证

固定 iPhone 17 / iOS 26.5 模拟器，测试库与真实用户数据隔离。

- `MentorFeatureStoreTests`：97 项通过，包含单条选择、仅所选材料进入首轮请求、来源恢复、旧草稿保存失败阻止切换及成功重试。
- `MentorPersistenceTests`：53 项通过，包含事务回滚、幂等和原闪念完整字段保护。
- `MentorResponseParserTests`：11 项通过，包含来源归属与 hash 校验。
- UI 单条闪念路径通过：选择 → 交流 → 查看原文来源 → 无 Key 提示 → 结束 → 历史恢复 → 原闪念仍在。
- UI 注入写入失败路径通过：留在闪念页、原文仍在、错误靠近所选条目、按钮可以再次尝试。成功重试另由 Store 测试覆盖。
- UI 首页进入闪念、首次自动聚焦、输入框内收起键盘与麦克风可达性通过。

单元证据：`/tmp/mingsi-input-verified-20261003.xcresult`（182 项单元／集成测试通过；同一 bundle 的交流键盘 UI 曾失败，不能视为整个 bundle 通过）。

上述三条 UI 的修订后证据：`/tmp/mingsi-input-final-ui-20261003.xcresult`（这些用例分别通过；该 bundle 的理解编辑用例曾因字段标识未移入组件而失败，后续单独修正并复跑，见共享语音验收记录）。

## 首次理解保存卡死修复

扩大回归发现空白交流的首次理解防抖保存只排入 save，没有先创建理解草稿，导致导航保存不断循环。现在首次真实编辑串行排入 begin → save；创建失败仍保留文字，必须显式重试，不自动把失败视为成功。新增首次防抖编辑／本地确认测试通过，已有保存失败重试及阻止切换用例也通过。两个旧测试更新为先写入真实内容再断言已持久化草稿，继续验证最后一次输入、防抖版本和本地确认。
