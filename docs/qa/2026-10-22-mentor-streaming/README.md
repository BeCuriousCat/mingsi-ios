# 导师 SSE 与等待恢复验收 · 2026-10-22

## 问题与最终行为

此前 Responses 虽请求 SSE，仍由 `complete` 累积完整 JSON 后才返回；Chat Completions 导师请求为非流式。页面没有正文增量，并叠加 Store、审计网关和传输三层 30／120 秒总截止。不能把历史所有失败都归因于该机制，原始失败缺少足够网络证据。

本轮导师回应与「整理理解」均使用 SSE，通过请求专属进度通道向界面解码顶层 `body`／`text` 预览。生产网络仍走中央入口和严格所有权审计的 `complete`；通用 `stream` 对导师的绕过保护保留。完整结果收到明确完成事件，并经格式、来源、质量门和事务保存后，才成为正式条目。没有改变 Prompt 2.17.0／理解草稿 2.6.0 或 schema 1。

共享计时器以最后一个非空输出文本 token 续期：首个内容前从提交开始最多等 600 秒，之后连续 600 秒没有内容才截止。持续生成可以超过旧总预算。心跳、生命周期事件、模型推理不延长应用层内容预算。URLSession 默认空闲预算 600 秒；自定义较短的网络预算、连接错误、上游超时和系统后台限制仍可更早中断，SSE 不能保证永不超时。

失败保留当前页可复制的正文预览，标记「未完成的回应」。预览只在内存，退出／重启不承诺恢复；用户原话和已有完整交流仍由原仓储持久化。手动重试创建新 attempt 重新生成，不是断点续传。没有自动重发、JSON 修复调用或格式降级；一次操作仅一次 HTTP，取消及配置切换后的迟到内容不能覆盖当前会话。

## Agent Loop 的范围

现有应用已有受控流程：准备上下文 → 一次流式生成 → 校验／保存 → 等用户继续。它支持多轮交流，但没有自主工具执行或无限模型循环。本轮把流式、等待、取消和不完整结果纳入同一请求生命周期；没有引入额外 Agent 框架。用户已确认指 Pi／pi-mono，已通过认证 gh 检查固定源码。[Pi 接入评估](pi-assessment.md)记录：原生 Swift 对话继续使用现有受控流程；以后出现自主只读检索和多步工具需求时再评估服务端 Pi。Pi 底层错误／取消也会退出，重试不是 SSE 续传；无现成 Swift 包，Node RPC 需额外桥接服务。未安装、部署或转交凭据。
