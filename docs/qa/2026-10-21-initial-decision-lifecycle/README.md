# 初始建议的恢复与迟到结果边界

日期：2026-10-21。前一轮已改善导师选择标准，本轮检查 Today「直接讲解」的生产流式路径时发现：恢复既有讲解/追问，只要还有训练建议且没有回答复盘反馈，就会重新发起初始事项诊断。该请求的成功仅检查事项 id，失败甚至不检查当前事项/阶段。因此用户已经阅读、继续回答、修改原文或退出时，旧判断和错误仍可能进入当前页面。

## 修改

- 已保存的讲解与问题直接恢复；初始诊断仅属于尚未完成的视角选择，旧本地建议也只在该步骤重新评估。不是把历史建议认定为永久有效。
- 重开事项、回到概览、主动选定/接受视角、确认任意视角继续、重置与模型配置刷新均取消并失效旧初始请求。
- 接收成功和错误时同时核对请求 token、日记录、事项、阶段、模式、完整确认卡片和是否已进入问题/讲解；同一来源 id 的正文改变也使旧结果无效。不从旧响应补造新判断。
- 只对仍然属于当前选择阶段的失败显示错误。已离开的请求不向概览添加“无法完成当前判断”。完成时清理请求句柄。
- 注入初始建议服务与其他服务保持一致，便于用不响应取消的客户端验证；生产仍由现有中央模型服务组装，没有新增本地关键词判断、Prompt 版本或迁移。

## 修改前的真实反例

[基线摘要](evidence/baseline-summary.json)：**1 通过、4 失败、0 跳过**，原结果 `/tmp/mingsi-initial-decision-baseline-20261021.xcresult`。四项分别复现：保存讲解/问题重开仍发请求、用户带透镜继续后旧初始响应覆盖、退出后旧失败污染概览、相同卡片 id 但正文已改变仍接收旧诊断。正例证明未完成选择仍能正常请求。

这些使用真实 SQLite repositories 与可控 transport，只证明生命周期和请求次数，不证明真实模型语义。原失败保持原样。

## 实际模型：流式直接讲解与保存重开

直接讲解验收改用生产流式 `TodayAIService → DirectGLMClient` 和实际 `AppStore` 提交、保存、重新打开同一 SQLite 文件。沿用已授权 CC Switch 当前伊莉丝 HTTPS Responses，配置别名 `gpt-6.1-sol`，只发一条新的可逆决策合成输入：一周内可退学费、已花时间不可恢复，请解释这个区别，不替用户决定是否报名、不提问、不要求先报名试试。

**在线 1 通过、0 失败、0 跳过**，原结果 `/tmp/mingsi-direct-stream-live-20261021.xcresult`，见[摘要](evidence/live-stream-summary.json)。捕获实际流式调用一次、非流式 complete 零次、HTTP 尝试一次、完整 completed 标记，maxRetryAttempts=0；没有重试或补发。请求、拼接后的原 assistant 文本及持久化状态均保留。

Codex AI 已逐条审读[实际正文与语义结论](evidence/live-stream-semantic-review.json)：说明学费期限内可退、时间不可恢复，所以只是部分可逆，并不意味着无成本或学习没有价值；不代用户决定、不提问、不安排试验，没有能力提升断言。正文四句，来源为本次确认卡片。通过真正的保存动作返回，再用新 store/repositories 打开同一 SQLite 文件，讲解及来源保持一致，没有新行动或原则，该 harness 重新打开没有模型调用。

这里直接进入已确认卡片的思考步骤，未连初始组织/推荐与辅助提示服务，**不能把该 harness 的一次调用扩张为所有生产辅助服务都零额外调用**。它也没有 UI driver，不是网络 UI 全流程。原机会成本非流式 30 秒超时仍在[旧报告](../2026-10-21-direct-explanation/README.md)保留；新场景成功不抹去旧失败，也不证明失败原因或稳定成功率。
