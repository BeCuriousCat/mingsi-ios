# 明思 Product Brief

## Mission

明思帮助忙碌的知识工作者把每天零散、混乱、容易被忽略的想法，训练成更清晰的判断、更高价值的行动和可验证的成长。

产品不替用户思考。产品提供一个稳定的训练循环，让用户持续把事情想清楚、做出来、再校准。

## Slogan

不替你思考，而是训练你把事情想清楚。

## Target User

第一版只面向一个 alpha 用户画像：

- 忙碌的个人知识工作者。
- 执行快，但不一定总能先把问题想清楚。
- 工作环境中存在隐私约束，不能把原始公司资料直接复制到外部工具。
- 愿意每天花 10-15 分钟、每周花 15-20 分钟进行复盘和校准。
- 愿意把自己的思考过程沉淀成长期资产。

初始 alpha 用户就是产品拥有者本人。

## Core Problem

用户每天会遇到很多事件、决策、阻塞、情绪和临时想法，但这些内容通常不会稳定地被转化成：

- 清晰的问题定义。
- 明确的假设和风险。
- 高价值的优先级选择。
- 明天可执行的具体动作。
- 对自己判断质量的长期证据。

普通笔记、日记和待办工具主要记录信息和任务，不负责训练用户把事情想清楚。

## Core Loop

明思的核心训练闭环是：

```text
Clarify -> Challenge -> Choose -> Act -> Calibrate
```

- Clarify：把混乱输入整理成结构化内容。
- Challenge：用透镜质疑假设、证据、机会成本和替代解释。
- Choose：收敛到一个主任务和少量次要任务。
- Act：在现实中执行。
- Calibrate：对照预期和实际结果，调整判断。

## MVP Scope

第一版包含：

- 每日文本输入，支持系统输入法或第三方输入法语音转文字。
- AI 辅助整理成可编辑思考卡片。
- 用户确认、修正和排除敏感内容。
- Quick / Standard / Deep 三种训练模式。
- 思考透镜和深度追问。
- 明日主线任务和最多两个次要任务。
- 次日验证任务完成情况和实际价值。
- 周度和月度的基础成长指标。
- 最小原则库，用来沉淀可复用的行动准则。
- 本地优先的产品行为。
- Apple 本地通知提醒。
- GLM 直连模式，用户自带 API Key。

## Non-Goals

第一版不包含：

- 服务端代理。
- 用户账号体系。
- App Store 发布准备。
- 自研语音识别。
- Apple Calendar / Reminders 同步。
- 完整角色卡系统。
- 外部框架包市场。
- Mirror Cards。
- 能力图谱。
- Schema 动态 UI。
- 复杂动画系统。
- 团队协作功能。
- 社交功能、排行榜或分享机制。

## Product Principles

- 训练，不替代：AI 负责引导，关键判断由用户完成。
- 低日常成本：单次日常训练应可在 10-15 分钟内完成。
- 先结构化，再总结：先把输入整理成可编辑对象，再生成建议。
- 用户确认的事实优先：最终输出必须基于用户确认后的卡片和答案。
- 证据优先：所有建议都应区分事实、推断、假设和验证需求。
- 反信息茧房：重要建议必须保留反方视角或替代解释。
- 隐私优先：默认鼓励抽象表达和脱敏输入。

## Success Metrics

早期成功以行为变化衡量，而不是内容数量：

- 用户在 7 天内完成至少 5 次完整日常闭环。
- 用户在一周内至少 4 次完成次日验证。
- 至少 70% 的主任务有明确完成标准。
- 每周复盘能识别至少一个重复模式、偏差或阻塞。
- 使用一个月后，用户能看到思考框架或执行方式的前后变化。

## MVP Value Hypothesis

如果明思能把一次混乱的日常输入，转化成结构化卡片、针对性追问、一个高价值明日任务和次日验证，那么用户会更专注、更有判断感，并逐步提升执行可靠性。

## First Validation Milestone

用产品连续手工使用 14 天，验证：

- 用户是否愿意回到第二天继续验证。
- 周度报告是否能发现有用的重复模式。
- 明日主线任务是否比普通待办更能推动执行。
- 原则库是否能成为可持续的长期资产。
