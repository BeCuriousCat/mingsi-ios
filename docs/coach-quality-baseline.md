# Coach Quality Baseline

本阶段目标：建立“教练质量基线”。明思下一阶段不追求新增大功能，而是让 Today 流程稳定从“复盘记录工具”进入“个人思维教练”的第一版稳定形态。

## Product Direction

明思不是 AI 答案工具。它的核心工作是帮助用户训练基础能力：

- 沟通力：把一件事讲清楚，让别人能复述背景、对象、问题、行动和结果。
- 思考力：看见证据缺口、判断跳跃、条件差异和反例。
- 执行力：把思考后的判断变成足够小、能执行、能留下证据的一步。
- 校准力：用明天的真实结果更新今天的判断，不把完成打卡当作有效结果。

## Required Today Flow

Today 流程必须稳定支持：

1. 用户输入一件事。
2. 明思指出当前主要缺口：讲不清、证据不足、判断跳跃、行动不可验证、旧经验误用。
3. 明思把缺口归到基础能力：沟通力、思考力、执行力、校准力。
4. 明思只给一个最小训练动作，避免一次抛出多个问题。
5. 用户可以补充，也可以带着缺口继续；继续不代表缺口消失，明天要用结果校准。
6. 历史记录沉淀常见思维模式，但不能把全部历史塞进每次 Prompt。

## Ability Model

| Ability | Common gaps | Minimal training actions |
| --- | --- | --- |
| 沟通力 | 背景缺失、对象不清、代词不明、别人无法复述 | 补一句背景；写清“谁的什么问题”；用一句话复述前因后果 |
| 思考力 | 证据不足、判断跳跃、旧经验误用、反例缺失 | 分开事实和解释；写出判断依据；判断旧经验是复现、调整还是否定 |
| 执行力 | 行动过大、行动替代目标、缺少完成证据 | 写一个最小行动；写出完成后留下什么证据；先明确成功标准 |
| 校准力 | 明日验证不可检查、结果信号模糊、完成不等于有效 | 写出可观察信号；写清出现什么结果就确认、调整或推翻判断 |

## Stop Conditions

本阶段只有同时满足以下条件，才可以停止并进入下一阶段：

- 有一套明确的能力模型，至少包含沟通力、思考力、执行力、校准力，并能映射常见缺口和训练动作。
- 有黄金案例集，至少 20 条典型输入，覆盖流水账、背景缺失、对象不清、证据不足、判断跳跃、行动替代目标、旧经验误用、明日验证不可检查。
- Today 流程能稳定跑通：输入 -> 明思指出主要缺口 -> 用户补充 -> 明日验证 -> 次日校准。
- 教练输出不再像系统说明，主路径不暴露高成本术语。
- 相关 StateMachine、UI 测试通过，`xcodebuild build` 通过，工作树干净，有提交点。
- 至少一次真实手机试用通过：用户能感觉明思在训练自己，而不是只是要求填表。

## Allowed Work

只允许做直接服务教练质量的工作：

- 改 Coach Engine：缺口判断、训练动作选择、是否允许带着缺口继续。
- 改 Prompt：围绕听懂、指出缺口、给最小训练动作，不能堆长规则。
- 改思维透镜：让透镜服务教练决策，而不是让用户自己挑 Prompt。
- 改 Today 流程和文案：减少解释性文案，降低术语成本，突出当前要做什么。
- 增加黄金案例和测试：用它们防止两三个月后迭代腐化。
- 增加轻量能力画像：记录常见缺口，但不做复杂画像系统。
- 改本地记录结构：只为保存训练证据、复盘结果、明日验证和校准结果服务。

## Disallowed Work

本阶段不允许做会稀释主线的工作：

- 不做商业化功能：订阅、会员、付费墙、价格策略。
- 不做同步和账号系统：除非本地使用被严重阻塞。
- 社交和分享：产品内社交、广场、分享模板。
- 复杂报表：成长报告可保留基础能力，但不能扩成仪表盘。
- 窄场景功能：系统设计、产品方案、会议复盘等只能作为案例，不能变成固定功能。
- 复杂装饰 UI：视觉可以优化，但不能让用户更难完成训练。
- 不无限加 Prompt 规则：失败先进入黄金案例，再判断是否抽象成通用原则。
- 不让 AI 直接给结论：明思可以建议，但必须先说明基于什么、缺什么、用户要补什么。

## Lightweight Pattern Memory

历史记录只沉淀为轻量模式摘要，不把全部历史原文塞进每次 Prompt。

- `CoachPatternSummaryPolicy` 只读取最近已完成记录，最多分析 14 条。
- 摘要只保留常见缺口、基础能力、次数、最近一次最小训练动作和来源记录 id。
- `generateQuestions` 与 `generateQuests` 可以读取摘要；`organizeCards` 不能读取，避免原始材料整理被历史解释污染。
- 摘要只能作为弱提示：先看今天材料，如果同一模式复现，再选择一个最小训练动作。
- 当前阶段不做复杂画像系统，不展示复杂报表，不把用户贴永久标签。

## Stop-Gate Command

阶段停止前运行：

```bash
scripts/run_coach_quality_baseline_gate.sh
```

这个脚本会检查黄金案例、核心教练测试、StateMachine、UI、build，以及真实手机试用证据。真实手机试用证据记录在 `docs/coach-quality-phone-trial.md`；状态不是 `PASSED` 时，阶段不能关闭。

## High-Cost Terms Guardrail

Today 主路径不应出现这些面向用户的高成本词：训练处方、审计、闭环、校验依据、能力诊断、推进标准、训练契约、底盘检查、过往经验复现。

允许在内部代码、历史迁移、测试反向断言、Prompt 规格中解释这些概念，但用户主路径要改写成更直白的话，例如“这次先练”“还缺什么”“怎么算讲清楚”“改选记录”。

## Golden Cases

黄金案例保存在 `docs/coach-quality-golden-cases.json`。每条案例必须包含：

- `input`: 用户可能真实输入的一段内容。
- `expectedPrimaryGap`: 当前最主要缺口，只能选一个。
- `expectedAbility`: 主要训练能力，只能选一个。
- `minimalTrainingAction`: 明思应该要求用户做的一个最小训练动作。
- `shouldNotDo`: 明思不应该做的事。
- `coverageTags`: 案例覆盖的风险标签。

这些案例不是为了锁死输出文案，而是为了锁住教练判断方向。
