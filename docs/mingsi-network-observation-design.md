## 1. 先固定本批究竟在测什么

正式批次前登记同一构建、Prompt/内容版本、协议、服务配置代号、模型别名、温度、输出上限及参数字段。准确上游身份和费用无法核实时分别记未知；第三方转发的别名不能当作官方模型认证。沿用已授权服务，不读取或公开Key，不在本设计阶段执行模型请求。

当前50次预登记、至少7天、48次完整可用及10段多轮门槛不变。应用请求、底层交易和完整可用结果分别报告。每次重试、重定向等额外网络交易都占实际请求预算，不把一个按钮或一个请求行当作一次HTTP。不得因失败自动补足50次成功。

正式窗口开始前必须明确如何对账应用请求与系统交易，并保留预连接失败、取消、缺少原生指标的记录。若原生计数未知，不能假设还剩预算并继续自动发送；若发现实际交易超出预登记上限，保留超限事实，不能删掉多出的交易使该批看起来合规。这里没有承诺URLSession内部只会发生一次底层交易。

## 2. 服务端输出预算

| 支持合同 | 发送字段 | 已核对的语义与边界 |
| --- | --- | --- |
| 官方Responses | `max_output_tokens` | 覆盖推理、可见正文及非可见格式token；达到上限可能在正文出现前就以incomplete结束 |
| 官方OpenAI Chat | `max_completion_tokens` | 覆盖可见输出及推理；旧 `max_tokens` 已弃用且不兼容o系列 |
| 官方Z.AI Chat | `max_tokens` | 官方参数是模型输出token上限；当前页面未给出与OpenAI相同的推理预算保证，不跨供应商推断 |
| 自定义兼容服务，包括当前订阅转发 | 待核对的明确参数合同 | 不能仅由协议名推断参数支持或服务实际执行预算；保留“已发送字段”和“兼容性证据”两项 |

先在请求模型中保存有限的正整数预算和明确参数类型，再按对应合同组装请求。未知供应商不通过失败后删字段、换字段或隐藏重试来碰运气。不能同时发送两个互相竞争的上限字段。应用字符截断及Prompt中的“简短”不是服务端token预算。

当前工程默认值为：Chat导师请求8,192，Responses导师请求16,000；这是为了给推理和结构化正文留出空间的工程默认值，不是正式窗口的成本或质量承诺。不得直接从中文回复字数推定推理模型所需token；过小会使没有正文的请求仍消耗输入和推理额度。正式观察前仍需固定批次值及选择理由，任何调整均记录新配置，不将两种配置拼成一次通过率。服务定价未核实前只报告请求数、配置预算和服务自报用量，不声称具体人民币费用上限。

## 3. 关联身份与最小存储

独立于回复提交的本机传输观测表已关联 `MentorAuditToken` 的session/request/epoch/semanticRevision及LLM `traceID`。每次实际派发另有不透明attempt ID；URLSession的taskIdentifier只在该次session内有效，不能单独作为全局主键。v75保存基本观测，v76追加预算，新的v77追加数字自报用量；下表是完整目标，其中配置、model与阶段时点尚未实现。

| 字段组 | 拟保留内容 | 缺失处理 |
| --- | --- | --- |
| 身份 | request/attempt ID、所属session、epoch、语义版本、配置及观测schema版本 | 不猜关联；拒绝串到当前另一轮 |
| 派发 | 应用派发开始/终态、实际所发预算字段和值、协议 | 未知兼容合同不猜字段；缺派发回执不等于没有网络请求 |
| 原生指标 | 指标接收状态、系统交易总数、networkLoad/localCache/unknown各类数量、redirectCount | 原生指标缺失或类别未知均显式保留；不填成0或1 |
| 时间 | 单调起点到首次可读正文、首次界面可见正文、传输终态、正式保存的独立耗时 | 从未发生的事件为null，不能用终态耗时代替首字 |
| 用量 | 服务自报input/output/total及reasoning子项、字段来源、返回model | 缺失为null；明确自报身份，不升级成已验证上游 |
| 结果 | 成功、失败、取消、中断、超时、输出上限等固定分类；观测写入失败状态 | 未保存完成的结果不能记完整可用 |

不存请求/响应原文、音频、认证头、URL或查询参数、IP、证书信息、系统原始错误字符串。配置代号不能由Key哈希生成。观测不新增外部遥测；私人导出和公开去标识汇总分别处理。

## 4. 派发、取消及迟到事件

当前 `PromptTracingLLMClient` 的正文审计要求请求仍拥有当前epoch，适合阻止旧回答提交，不能直接拿来保存取消后的原生计数。拟保留独立的只写观测通道：它只能更新所属旧请求的计数和时序，不能恢复请求状态、追加回答、修改草稿或创建会话。

在实际URLSession调用处绑定每次attempt的delegate，采集 `didFinishCollecting`。原生交易按Apple的resourceFetchType分类；总数组长度、networkLoad数和重定向数分别保存，缓存与unknown不混称网络请求。该数据仅代表系统可报告范围，不能证明转发服务背后没有继续重试。

delegate回调不得同步等待主线程或数据库。转换为无私密字段的Sendable快照后，通过明确的序号/事件ID归并到本机表；重复回调幂等，取消、失败和已提交后的迟到计数仍归原请求。删除会话后丢弃迟到回调，不重建被删记录。回调顺序、去重和写入失败均须验收；观测缺失不能被一条“成功”的派发日志覆盖。

进程中止后未收齐的指标保留未知，不推断取消成功或HTTP次数。不能因为前台已返回就停止等待必要计数，也不能为了收齐指标阻止用户退出；批次汇总再明确标出未收齐项。

## 5. 正文出现的三个时刻

1. 传输首次解析到非空的用户正文：沿 `MentorStreamProgress` 的顶层body/text解析记录；JSON键、内部推理、心跳不算。
2. 当前前台页面的非空正文实际与阅读可见区相交：需要界面几何观测，排除导航栏、固定输入区、键盘和离开页面。仅赋值State、onAppear或isHittable不足以证明。指标描述为“界面可见”，不推断用户读过或理解。
3. 请求终态与回复正式保存：分别记录；失败预览可以有首份正文时间，但没有完整可用回复。

所有时长来自同一请求起点的单调时钟；不能跨进程恢复旧Instant继续计时。切换、取消和迟到预览不得污染下一请求。汇总p50/p95时分别给样本数、缺失、失败及纳入规则；无正文失败不能消失在一张看起来很快的延迟表中。N01既有9985ms仅为终态耗时，保持原定义。

## 6. 无模型请求的实现验收

- 实际编码请求预算，验证协议/服务合同选择、无效预算拒绝及HTTP400后不删字段重发。
- URLProtocol覆盖派发开始、HTTP失败、取消、无指标；另以本机HTTP服务覆盖真实系统指标和重定向，不能从URLProtocol fixture推断原生指标支持。
- 验证多attempt和多交易不合并成1、回调乱序/重复、写入失败、取消后归属、删除后不复活、数据库重开及旧版本迁移。
- Chat usage-only事件在choices为空时仍提取用量，缺失/中断保持未知；Responses/Chat的输出上限均保持失败，预览不冒充完成。
- 前台界面测试分别验证正文解析、布局可见、取消后迟到事件和保存；截图在手动滚动前采集。真实供应商兼容性另登记，不用离线测试代替。

上述实现和验收、当前输入区候选及真实网络基础场景通过后，才准备正式7天/50次窗口。原N02/N03属于先前有界基础批次，不自动移作正式窗口；本文新增模型调用0。
