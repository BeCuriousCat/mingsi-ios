# 明思产品重置 PRD

状态：提案，待一个真实用户完成 14 天验证
版本：0.1
日期：2026-09-06

这份文档从产品实际意义重新定义明思。它不把现有页面、数据结构、事项模型或图标方向当作既定前提；现有实现只作为可复用的技术资产，不能反过来决定产品。

## 1. 先给结论

明思的方向是成立的，但当前产品把三个不同产品混在了一起：日记整理器、任务复盘器和能力成长系统。用户真正愿意反复打开的价值只有一个：

> 在一个重要但混乱的时刻，帮我看清我漏掉的关键点，并让我马上做出自己的下一步。

“第二天验证、长期成长、项目原则、支线奇遇”都可以成立，但它们必须服务于这个瞬间价值。它们不能成为每天使用的前置成本，也不能要求用户先维护一套复杂的资料库。

当前主要弯路有四个：

1. 把一次完整训练设计成默认入口，用户必须先输入长材料，才能得到价值。
2. 把事项、项目、成长指标、原则、验证和奇遇同时放到产品中心，导致用户不知道今天到底要解决什么。
3. 用大量结构化状态表达产品完整性，却没有先证明“短暂使用一次就有帮助”。
4. 过早为品牌图标寻找完整隐喻，反复生成骰子、灯具、翻面、文字和抽象物件，结果是图形承担了产品说明书的工作。

因此下一阶段不是继续堆功能，而是验证一个低门槛、即时有用的核心回路。

## 2. 产品定义

### 2.1 一句话

明思是一个在关键时刻帮用户看见思维盲点、形成下一步行动的个人思考外挂。

### 2.2 用户任务

当用户遇到以下任一情况时打开明思：

- 事情很多，不知道当前最该处理什么；
- 已经形成一个判断，但担心自己只看到了一个角度；
- 情绪或压力让问题变得模糊；
- 想做一件事，却说不清完成标准；
- 做完之后想知道自己的判断哪里准确、哪里需要修正。

明思的输出不是答案，而是一个更清楚的问题、一个被看见的盲点，以及一个用户认可的下一步。

### 2.3 核心承诺

用户每次使用 30 秒到 5 分钟，至少得到以下一项可感知收益：

- 发现一个原先没有考虑的关键因素；
- 把事实、猜测和情绪分开；
- 找到一个值得先做的动作；
- 确定一个可以在现实中检查的结果。

如果一次使用不能带来上述收益，产品应直接承认“不足以判断”，而不是输出冗长总结。

### 2.4 不做什么

明思不做通用笔记、会议纪要、任务管理器、情绪陪伴、知识问答、人格测评和游戏化打卡工具。它可以保存用户产生的材料，但保存不是主要价值。

## 3. 核心体验：明思一下

### 3.1 入口

任何时刻，用户可以用一句话、一段语音或一张现场照片开始。入口名称统一为“明思一下”。

首屏只要求一个输入：

> 现在什么事情卡住你了？

用户可以只写 5 个字，也可以写完整背景。不要求先整理、不要求选择项目、不要求选择训练模式。

### 3.2 一轮交互

中央 LLM 接收当前输入和极少量、经过用户授权的相关上下文，判断这一轮最值得处理的思维缺口。它只能选择一种主动作：

| 主动作 | 适用时机 | 用户看到的结果 |
| --- | --- | --- |
| 澄清 | 事实、对象或问题边界不清 | 一个具体澄清问题 |
| 反看 | 用户过早接受了单一解释 | 一个替代解释或反证问题 |
| 取舍 | 选项太多、重点不明 | 一个优先级问题 |
| 落地 | 判断正确但无法行动 | 一个完成标准问题 |
| 校准 | 已有真实结果 | 一次预期与结果的对照 |

一轮最多提出一个问题。用户回答后，LLM 返回一张短回执：

1. 我听到的事实；
2. 可能漏看的点；
3. 由用户决定的下一步；
4. 是否值得留下验证。

回执默认不超过 120 个中文字符。用户可主动点击“再想一层”，才进入下一轮。

### 3.3 结束条件

一轮在以下任一条件满足时结束：

- 用户确认下一步；
- 用户选择只保留这个提醒；
- LLM 判断证据不足并明确说明需要什么信息；
- 用户主动结束。

默认不创建事项、任务、原则或成长记录。只有用户明确选择“留下验证”，才生成一条可编辑的验证记录。

### 3.4 长流程入口

用户确实需要处理多件事情时，才从“明思一下”进入“今日整理”：

```text
多条短记录 -> LLM 建议分组 -> 用户确认 -> 选择一件进入训练 -> 形成验证
```

长流程是放大器，不是首页门槛。它保留现有多事项能力的价值，但不要求所有用户每天完成完整闭环。

## 4. LLM 中心与本地职责

### 4.1 LLM 是判断中心

所有需要理解语义、判断缺口、选择追问、决定引用哪些历史材料、判断是否值得形成验证的动作，都由中央 LLM 完成。客户端不使用关键词规则假装完成思考。

中央 LLM 负责：

- 从原始输入中识别当前用户真正要解决的事情；
- 选择本轮唯一主动作；
- 生成一个具体问题和必要的反方视角；
- 判断回答是否足以形成下一步；
- 从用户授权范围内挑选相关历史证据；
- 在验证后更新原判断，并生成可回链的证据描述。

本地代码负责：

- 保存输入、回答、请求和结果；
- 执行用户同意、隐私边界、重试、撤销和删除；
- 保证事务、关系完整性和当前会话隔离；
- 控制请求次数、超时和离线状态；
- 提供通知、照片权限和系统快捷入口。

本地规则可以处理纯界面状态和安全门禁，不能生成产品判断、教练问题或成长结论。

### 4.2 Prompt 上下文

每次请求只包含：

- 当前输入和本轮回答；
- 用户明确选择的相关事项或项目；
- 最多 3 条有明确来源的历史证据；
- 当前流程版本和输出 schema。

默认不发送所有历史、所有项目或全年成长记录。PromptRun 必须记录实际发送的来源 ID、模型、版本和结果。

### 4.3 失败体验

模型失败时保留用户输入，显示失败原因和“重试这一轮”。不生成本地假问题、不伪装成成功、不自动创建任务。用户可以离开，输入仍然存在。

## 5. 信息架构

底部导航保留四个区域，减少一级入口：

| 区域 | 任务 | 首屏内容 |
| --- | --- | --- |
| 明思 | 立即获得帮助 | 输入框、最近未完成的一轮、一个可选的到期验证 |
| 记录 | 回看来源 | 按时间排列的明思回执和验证证据 |
| 项目 | 只管理长期证据线 | 当前项目、阻塞、结束和恢复 |
| 设置 | 控制隐私和模型 | API、数据、通知、快捷入口和诊断 |

成长不再作为独立一级 Tab。成长证据在记录详情中出现，周期性总结从设置或记录页主动进入。这样用户打开 App 时面对的是行动，而不是仪表盘。

### 5.1 明思首页

首页从上到下只有四段：

1. “明思一下”输入入口；
2. 最近一轮的继续入口；
3. 一条到期验证（若有）；
4. 最近三条回执。

不要在首页同时展示事项列表、成长分数、项目统计、奇遇卡和长说明。

### 5.2 记录详情

每条记录显示输入、LLM 的一个问题、用户回答、回执和来源。验证记录显示预期、实际结果和判断更新。任何成长证据都能回到这条记录。

### 5.3 项目

项目只回答三个问题：为什么做、目前判断、最近证据。结束项目需要原因和实际结果；AI 总结是用户主动请求的附加动作。

### 5.4 支线奇遇

支线奇遇属于可选探索层，不进入核心首屏。它必须满足“轻、近、可拒绝、偶尔出现”：

- 根据用户明确提供的场景和偏好生成；
- 不能根据未经授权的精确位置、通讯录或后台行为推断；
- 每次只出现一个邀请；
- 接受、忽略、暂缓都不扣任何分；
- 完成后留下生活体验记录，可获得非竞争性的“体验记忆”；
- 不影响核心能力指标，不制造连续打卡压力。

奇遇的价值是让明思进入生活，不是把生活变成任务清单。第一版先用用户主动触发的“给我一个附近可做的小变化”，确认使用频率后再做随机出现。

## 6. 数据对象的最小集合

第一阶段只保留以下六类权威对象：

1. `NudgeSession`：一次“明思一下”及其问题、回答和回执；
2. `Verification`：用户主动留下的预期、实际结果和判断更新；
3. `Evidence`：可引用的事实、回答、行动结果或项目结果；
4. `Project`：跨日期的目标证据线；
5. `PromptRun`：每次 LLM 请求的审计记录；
6. `UserPreference`：用户授权的场景、隐私边界和提示偏好。

`TrainingCase`、成长结算、指导目录、原则和复杂事项关系可以继续存在于兼容层，但不再作为首阶段产品决策的中心。只有真实使用证明用户需要，才提升为前台概念。

## 7. Icon 设计原则

### 7.1 设计任务

Icon 不负责解释“澄清、挑战、行动、验证、成长”五个步骤。它只需要成为一个可记忆的品牌对象，让用户在关键时刻愿意打开明思。

### 7.2 硬约束

- 最终素材使用文生图 raster 生成路线；
- 图标内不出现汉字、字母、数字、标点、缩写、字标或伪文字；
- 不用脑、机器人、灯泡、指南针、骰子、靶心、相机、书本、对话气泡等品类符号；
- 不用一组元素讲完整产品流程；
- 先验证单色剪影，再验证颜色、材质、Dark、Tinted、灰度和 20px；
- 只保留一个主对象，主体轮廓在 32--60px 必须可命名或形成稳定识别；
- 任何候选若必须依靠提示词解释，直接淘汰。

### 7.3 推荐探索方向

先探索“一个安静但有张力的品牌对象”，而不是功能工具：

- 一个保留开放缺口的实体结构；
- 一个由两种视角共同形成、但不暗示答案的稳定形体；
- 一个在视觉上存在轻微视角变化、但不成为光学玩具的对象。

每轮只生成 3--4 个方向，先做无文字、无标签的概念板。独立盲审按第一眼对象、类目误读、20px、单色和品牌关系判定。没有方向通过，就回到概念，不进入生产。

### 7.4 生产顺序

```text
概念板 -> 独立盲审 -> 黑白母形 -> 外观适配 -> Asset Catalog -> Simulator
```

文生图结果只承担造型探索。最终生产图标必须是经过清理、尺寸检查和平台验证的 raster。任何字形方向，即使与“明思”名称有直接关系，也因文字约束自动失败。

## 8. 关键验收指标

第一阶段只看是否产生价值，不看记录数量：

| 指标 | 目标 | 观察方式 |
| --- | --- | --- |
| 首次使用完成率 | >= 80% 完成一轮 | 从首次输入到回执 |
| 单轮中位耗时 | <= 90 秒 | 入口到结束 |
| 即时有用率 | >= 60% 选择“看见了新点” | 结束时单击反馈 |
| 一周回访率 | >= 4 次 | 独立日期计数 |
| 明确下一步比例 | >= 70% 的完成轮次 | 回执中用户确认的行动 |
| 误导率 | < 5% | 用户标记“问题方向错了” |
| 上下文串线 | 0 次 | PromptRun 来源审计和人工抽查 |
| 验证完成率 | >= 50% 的主动验证 | 到期后 7 天内 |

失败信号包括：用户只在被提醒时打开、每轮都需要输入大段背景、回执太长、问题让用户觉得被评判、用户无法判断为什么这个问题与自己有关。

## 9. 实施里程碑

### M0：产品切片与观测（3--5 天）

- 建立独立的 `NudgeSession` 体验，不改动现有长期数据；
- 统计输入长度、模型耗时、问题类型、结束原因和即时反馈；
- 首页只提供一个明确入口；
- 用真实内容做 10 次内部走查。

通过条件：至少 8/10 次用户在 90 秒内完成，且能说出“这次多看到了什么”。

### M1：可靠的即时回执（1--2 周）

- 接入中央 LLM 的单问题协议；
- 保存 PromptRun、上下文版本和用户反馈；
- 完成失败、重试、取消、重启恢复；
- 加入语音输入和一键复制/粘贴。

通过条件：0 次输入丢失、0 次上下文串线、错误可恢复。

### M2：主动验证（1 周）

- 用户明确选择后才创建 Verification；
- 到期展示不阻塞新的“明思一下”；
- 保存实际证据与判断更新；
- 从记录详情回链到原问题。

通过条件：至少 5 条真实验证记录，用户能指出其中一条改变了自己的判断。

### M3：长流程按需接入（1--2 周）

- 将多事项整理降级为高级入口；
- 仅在用户有两条以上材料时提供分组建议；
- 保持单活动会话和来源隔离；
- 删除首页的结构化噪音。

通过条件：长流程不会降低即时入口完成率，且至少有 3 次明确的多事项使用需求。

### M4：生活探索与品牌资产（在 M1 后）

- 根据用户主动提供的信息生成近场支线奇遇；
- 记录接受、忽略、完成和体验反馈；
- 完成无文字 Icon 的概念、盲审和平台验收；
- 进行一次 14 天体验复盘。

通过条件：奇遇不干扰核心使用；Icon 通过独立盲审和小尺寸验收。

## 10. 需要冻结的工作

在 M1 通过前冻结：新的成长评分、复杂指导市场、全量历史智能搜索、账号同步、团队协作、Provider Profile、复杂奇遇规则、排行榜、连续打卡和完整项目管理。

冻结不是永久否定，而是避免在核心价值尚未被验证前扩大状态和维护成本。

## 11. 设计语言

产品界面应表现为“一个安静的判断工具”：

- 首页突出当前输入和一条回执；
- 每屏只要求用户做一个决定；
- LLM 的问题、用户的回答、事实和推断有明显层级；
- 颜色只表达状态，不用装饰色制造智能感；
- 空白、卡片和动效服务于阅读和回看，不服务于展示功能数量；
- 错误状态保留材料并说明下一步；
- 所有内容支持动态字体、深色模式、VoiceOver 和减少动态效果。

视觉上可以保留现有的温和、低噪声、原生 iOS 基础，但减少同时出现的卡片、状态标签、指标和入口。产品调性不是“精致的 AI 仪表盘”，而是“用户在压力下仍愿意打开的思考工具”。

## 12. 最终判断门槛

只有当用户在不准备长材料的情况下，能反复通过“明思一下”获得即时帮助，长流程、验证、项目和奇遇才有继续扩展的理由。若 14 天后即时有用率和回访率不成立，应优先改变问题选择和回执质量，不能用更多功能补偿。
