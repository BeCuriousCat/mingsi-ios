- 版本：1.1

- 状态：可供设计、技术拆解与评审的产品方案；尚未实施或通过使用验证
- 上位方向：[明思产品总纲](mingsi-mentor-product-prd.md)
- 落地设计：[系统分析与设计](mingsi-mentor-m1-system-design.md)、[功能点与交付拆解](mingsi-mentor-m1-feature-breakdown.md)、[接口契约](contracts/mentor-m1/README.md)

本文把总纲中的诉求转为产品决策。下文的默认行为、内容数量和评估判断线是本版采用的方案，不代表用户逐条确认过这些细节，也不代表已被数据证明。调整方案时同步修改受影响的流程、规则和验收项，不由各模块分别猜测。

## 1. 我们究竟要交付什么

交付一个用户在工作告一段落时可以直接打开的日常导师。用户可以让它带着回看一个片段，也可以不说任何事情就得到一份短讲解；有具体问题时可以直接讨论。一次交流之后，用户能够自由结束，并在以后找到当时的内容和自己的表达。

首版的具体价值是：减少寻找材料、寻找角度和组织表达的成本。长期能力提升需要后续现实证据，本版不承诺仅凭使用次数就能提升思考能力。

### 1.1 目标用户与核心任务

初始用户是持续开发、创作或做知识工作的人，首位试用者是产品拥有者本人。其关键任务是：

> 当我刚结束一段工作，觉得一天很忙却说不出有什么值得回看时，帮我从一个具体片段开始，或者给我一个能理解的新角度；我愿意的话，再帮我留下自己的表达。

“不知道什么时候用”首先通过明确的使用场景解决：一次工作结束后，有几分钟空闲时可以打开。它不是对 App 自动知道用户已经收工的承诺。提醒能否进一步帮助启动，在后续独立切片验证。

### 1.2 首版必须交付的产品包

| 决策 | M1 的确定方案 | 原因 |
| --- | --- | --- |
| 开始方式 | 带我回看、听一个新视角、我有一件事，共用一个交流页 | 同时满足无材料、想获得输入和已有问题 |
| 页面范围 | 改造 Today 主入口；增加最近交流列表和详情；保持现有五个 Tab | 让核心体验完整，同时控制全局导航迁移范围 |
| 新输入 | 内置 24 份经编辑审核的短内容，支持完整离线阅读 | 新用户无需积累历史或先配模型也能获得实际内容 |
| 导师回应 | 澄清、讲解、比较、建议、收束五类主动作 | 需要教学时可以直接讲，不把用户锁在答题流程 |
| 表达与留存 | 会话自动保存；用户主动整理的理解草稿经确认后成为其认可内容 | 区分交流记录、AI 草稿和用户结论 |
| 返回路径 | 最近交流可查看、继续、删除；当前会话可中断恢复 | 首版使用留下的内容当下就能找回来 |
| 模型接入 | 保留 BYOK；在线交流需配置，静态内容不需要 | 不让模型配置阻断所有首次价值 |
| 暂不新增 | 通知、后台材料接入、跨主题记忆、直接验证捷径、成长评分、内容市场 | 这些能力不作为完成一次导师帮助的依赖 |

24 份内容、首个默认条目和时间预算是本版具体取舍，可在试用后调整。首版不接实时资讯和开放式搜索，也不要求用户先选兴趣、建项目或做自评。

### 1.4 这份 PRD 必须支持的决策

产品的核心能力是：根据用户当下的材料和意愿，提供一个有依据、能理解的思考帮助，并让用户能够表达、纠正和再次使用它。首版将这种能力落实为回看引导、完整教学、具体问题交流和自愿整理理解。

一份可执行的 PRD 应让产品、设计、开发和验证人员对同一种情况做出一致判断。本文通过以下内容承担这个职责；章节齐全本身不代表方案有效。

| 必须回答的问题 | 本文的确定结果 | 完成判断 |
| --- | --- | --- |
| 为谁、在什么情况下解决什么问题 | 第 1 节的目标用户、使用时机、FR-01 至 FR-08 | 能指出一次真实使用的触发情况与预期帮助 |
| 用户从哪里开始，如何走到结果 | 第 2、3 节的页面、三条主流程和再次进入 | 没有材料、没有 Key 和不想整理均有可走通的路径 |
| 产品怎样提供帮助 | 第 4、5 节的教材、介入规则和输入输出 | 讲清内容从哪里来、导师何时问或讲、用户得到什么 |
| 发生中断、错误和分歧怎么办 | 第 6、7 节的保存、纠正、退出和异常 | 不靠开发者临时猜测，也不声称未保存内容已保存 |
| 本次做多少，现有能力怎样衔接 | 第 1.2、8、10 节的范围、兼容和工作包 | 能拆任务、识别依赖，并说清哪些能力尚未交付 |
| 怎么验收，什么证据支持继续投入 | 第 9 节的 T01 至 T18 和试用判断线 | 技术通过与真实获益分别有证据，允许结论是证据不足 |

例如，用户说“今天一直在开发，没什么可总结”：首页允许直接回看；导师先帮助找到一个片段；用户想不起来时立即可转为完整讲解；读完即可结束。用户想到“我只检查改完了，没有检查是否更好”，可主动整理为自己的表达，之后继续这件事时仍能看到原文。验收不仅检查页面走通，还检查用户是否认为这个区别对当前工作有用。最后一点需要试用，不能从生成了一段文字推断。

## 2. 信息架构与页面行为

### 2.1 页面清单

| 页面 | 首屏信息与主要动作 | 次级操作与返回 |
| --- | --- | --- |
| Today 首页 | 无未结束交流时主动作“带我回看”；有未结束交流时主动作“继续这次交流” | “听一个新视角”“我有一件事”；最近三次交流与“全部交流” |
| 交流页 | 展示当前片段或内容、对话正文及当前所需操作；正文为主要工作区 | 始终可结束；按需展示输入、换内容、整理理解和查看来源 |
| 理解草稿编辑页 | 可编辑正文及“保存为我的理解” | 取消返回交流，AI 草稿保持未确认 |
| 最近交流列表 | 按最后活动时间倒序；标题、日期、类型与简短预览 | 打开详情、删除；使用现有导航返回 |
| 交流详情 | 按顺序展示原话、讲解、来源及用户确认的理解 | “继续这件事”、管理理解、删除；返回原列表位置 |

标题优先使用用户原话的短预览；零输入会话使用教材标题。不得为了生成标题额外请求模型。所有页面在本版都应可达，不能将“回看”等到 M2 才补上。

原有完整今日训练保留可发现的“今日整理”入口，从首页展开进入。Projects、Growth、History 和 Settings 继续可访问；新导师流程不主动将用户送入模式或透镜选择页。

### 2.2 首页优先级（FR-01）

1. 显示一个主动作：恢复最近未结束交流，或开始回看。
2. 允许用户直接选择新输入、已有问题或单条闪念，不要求先解决旧交流。
3. 展示最近三次已产生内容的交流，再提供完整列表入口。
4. 旧验证提示、今日整理和可选探索放在次级位置，不抢占开始动作。

仅有未提交草稿也可以恢复。开始另一件事会先保存旧草稿并将旧会话置为暂停，不覆盖它；每次只允许一个前台导师请求。

未配置模型时，首页仍展示“听一个新视角”。用户准备发送文字进行在线交流时才说明需要配置，并提供设置入口；已输入内容保留，用户也可以转为阅读。

### 2.3 交互约束

每轮突出一个主要后续动作；工具操作使用原生导航、菜单与系统图标。内容类型决定布局，不把每段解释、来源或按钮组做成独立悬浮卡片。

输入采用系统文字输入，允许系统键盘听写；首版不新增独立录音或语音合成。保证 Dynamic Type、VoiceOver、深色模式、键盘避让、44pt 触控目标以及窄屏长内容可读。

## 3. 完整主流程

### 3.1 无准备回看（FR-02）

| 步骤 | 用户与系统行为 | 输出及转移条件 |
| --- | --- | --- |
| 进入 | 用户点击“带我回看” | 已配置模型时自动请求一个具体、低负担的回忆入口；未配置模型时先展示本地输入框，并保留“听一个新视角” |
| 提供片段 | 用户提交一句话或选择带入一条闪念 | 先保存，再向模型发送当前材料，进入等待态 |
| 找到角度 | 模型选择一次澄清、讲解、比较或建议 | 回应必须对应具体材料；最多一个问题 |
| 材料仍不足 | 用户补充，或明确表示想不起来 | 同次回看最多两轮补材料问题；达到上限仍无具体片段时，展示教材入口或收束，不再追问当天材料 |
| 获得帮助 | 已展示具体解释，或转入完整教学内容 | 可继续交流、主动整理理解或直接结束 |
| 结束 | 用户点击“到这里” | 立即保存并退出，不等模型总结、不要求评分或输出 |

回看开场不声称系统已观察过用户的一天。已配置模型时，首轮模型必须从“最后处理的事情、一次停顿、一个改动或一段沟通”等具体入口中提供一个可回复的起点；未配置模型时客户端仍保留本地输入页。模型负责语义理解和是否有足够材料；客户端只控制补材料次数、用户明确选择和流程状态。开场不占两次补材料预算；两次只限制导师主动索要缺失材料的次数，整个对话支持继续多轮，不作为能力评价。

### 3.2 零输入获得新视角（FR-03）

1. 用户点击“听一个新视角”，无需提交文字或提供历史。
2. 按第 4 节规则立即展示一份完整教材；记录条目及版本，静态阅读不调用模型。
3. 用户可以读完直接结束，也可以“换一个”“聊聊这个”或选择“不相关 / 已知道”。
4. “聊聊这个”后，用户提交问题或点击“举个例子”，才开始在线导师请求；教材内容及来源随该轮传入。
5. 用户由教材想到自己的经历，可以直接表达；系统沿用本次会话并标记本轮来源，不要求另开日记或重复输入。

同一自然日重复打开“听一个新视角”时，恢复该入口上次呈现且未被明确拒绝的内容和位置。“不相关 / 已知道”优先于自动恢复；用户主动“换一个”也会选择新条目。日期变化可以重新提供未读内容，不补发错过日期的材料。

### 3.3 已有具体事情（FR-04）

用户选择“我有一件事”或从单条闪念进入，提交现成材料。系统按当前需要直接回应；背景足够时无需再次询问“今天最后做了什么”。

用户明确要求“直接讲给我听”时，优先讲解；“给我建议”时可以提供有依据的建议；“你理解错了”时先接住修正后的事实。改变回应方式不清空已提交内容，不自动创建新的独立事项。

### 3.4 整理理解（FR-05）

“整理一下我的想法”只在用户已经提交了自己的表达后出现。用户点击后，模型根据当前会话生成草稿，进入编辑页。用户可以修改、确认保存、返回继续聊或直接结束。

只阅读教材时，可以“记一句自己的想法”，使用空白编辑区；不能从用户没有表达的内容中自动生成“我的收获”。原始对话自动保存与确认理解是两件独立的事。

### 3.5 结束与再次使用（FR-06、FR-07）

- 点击“到这里”不调用模型，立即结束当前交流；反馈入口可见但不阻塞返回。
- 退出后台或直接关闭页面时保存草稿，并标记暂停，不自动判定已完成或已有收获。
- 详情中的“继续这件事”追加新轮次，保留原文、教材版本和原先确认的理解；不覆盖旧问答。
- M1 的继续仅使用该会话链及用户明确带入的来源，不自动搜索其他项目和全部历史。
- M1 可以提供回到既有验证功能的次级入口，但不会把它伪装成新的直接验证流程，也不把完成验证作为本轮结束条件。

## 4. 新输入的内容系统

### 4.1 首发内容范围

首发 24 份教材，每份约 250-400 个中文字符，讲清一个中心意思。内容分为六组，每组四份；名称是编辑主题，不是用户必须完成的课程。

| 组别 | 首发四个主题 |
| --- | --- |
| 观察 | 看到的与推测的；正常变化与异常；第一次使用者的视角；顺利完成也有可观察之处 |
| 证据 | 判断依据从哪里来；什么会让我改主意；一次结果能够说明多少；不知道时先保留什么 |
| 取舍 | 目标与手段；做完与做对；下一步的机会成本；什么时候先不做 |
| 沟通 | 意图与实际表达；对齐完成标准；复述对方的问题；反馈与个人评价 |
| 迭代 | 改动与效果；先做小验证；返工的不同来源；什么时候停止继续修改 |
| 注意力 | 切换任务的代价；忙碌与重要性的区别；熟悉带来的忽略；给生活留一个观察点 |

这些主题包含工作和日常观察，不能据此推断某种职业一定缺少某项能力。内容负责人是本版产品负责人；实现方负责载入与呈现，未完成编辑审核的内容不得进入发布包。

### 4.2 单份教材契约

每份教材必须包含稳定 ID、版本、标题、主题、适用情境、观点、具体例子、适用边界、可选观察，以及来源类型和引用。页面显示来源类型；真实外部引用显示可访问出处。教学示例使用“教学示例”标识，不能假借名人或研究增信。

编辑审核检查：内容是否具体，是否无需答题也能理解，是否有适用边界，是否把观点冒充普遍规律，例子与出处是否真实对应。发布时 24 份都需有审核结果和版本清单；不能仅交付标题占位。

### 4.3 两份成品规格示例

下面两份展示首发内容应达到的具体程度，均为教学示例，不是真实用户记录或研究结论。

**示例 L01：改动之前，先说清希望什么变好。**

一个改动可以顺利完成，却仍然不知道有没有改善使用。动手之前，先写一句“我预计这个改动会让谁的哪一步更容易”，能让改完之后有一个检查方向。

例如，你把常用操作从菜单移到首页，希望第一次使用的人更容易找到它。按钮是否移好了，是交付检查；对方能否更快找到入口，是效果检查。可以请一个不熟悉页面的人完成相同的小任务，观察他停在哪里。这个观察能提供线索，但一个人的表现还不足以证明所有用户都会受益。

这不是要求每次修改都做正式实验。修复明确错误、满足无障碍要求，已经有直接的判断依据。这个角度更适合“总觉得不够好，却说不清还要改什么”的时候。愿意的话，拿最近的一次改动，试着写出希望谁的哪一步变容易。

**示例 L02：给观察和解释各留一个位置。**

我们描述一件事时，经常把看到的情况和对它的解释放在同一句话里。把两者分别说出来，可以保留更多理解事情的空间。

例如，“对方没有回复，所以他不重视这个需求”包含了两个层次：目前没有收到回复，是你能确认的情况；不重视，是一种解释。还有哪些情况可能产生同样的现象，需要结合约定的时间、对方是否收到，以及事情是否需要回复来判断。先分开，不代表原来的解释一定错误，也不要求永远替别人寻找理由。

这个方法适合信息有限却已经形成强烈结论的时候。如果你已经有多次直接证据，就可以据此作出判断。愿意的话，想起最近一句带着“所以”的描述，看看前半句提供了什么观察，后半句加入了什么解释。

### 4.4 选择与去重规则

| 条件或操作 | 首版确定行为 |
| --- | --- |
| 全新用户直接听讲 | 展示 L01；它是默认编辑内容，不标为“为你发现” |
| 无具体材料，再次请求新内容 | 按内容包编辑顺序展示下一份可用条目，不调用模型伪造个性化理由 |
| 用户已主动发起在线交流且有当前话题 | 同一次请求中提供合法候选；中央模型选择相关条目或返回暂不推荐，不为选题追加请求 |
| 同一天重复进入听讲入口 | 恢复上次仍有效的内容；已经标记不相关或已知道时选择新候选 |
| 换一个 | 排除本次会话已经呈现的条目，选择下一份候选；原内容可在会话中找回 |
| 不相关 | 当前会话排除该主题；不推断成永久兴趣，也不跨会话自动禁用 |
| 已知道 | 今后自动推荐排除该条，用户仍可从已读记录访问；设置中可以重置这类反馈 |
| 已经呈现过 | 当前本地日期及此前 13 个自然日不自动作为新条目推荐，按逻辑条目 ID 去重；同日恢复与用户主动回看不受此限制 |
| 所有候选都被排除 | 明确显示暂无新条目，提供已读回看或结束；不能循环包装成新内容 |
| 模型无法选中或失败 | 保留当前材料；提供明确的“看看通用内容”操作，由用户选择后按编辑顺序阅读 |

相关性判断属于模型职责；编辑顺序、版本、去重和用户明确排除属于本地约束。模型不得使用不在候选中的 ID，也不得因为用户没有材料就编造其过去经历。

进入静态听讲、从已输入话题转为阅读、点击“换一个”都使用本地编辑顺序，零网络请求。已有话题不会隐式触发相关教材选择。

## 5. 导师如何决定每轮做什么

### 5.1 介入规则

| 主动作 | 选择依据 | 必须提供的内容 | 默认长度建议 |
| --- | --- | --- | --- |
| 澄清 | 当前缺少会影响理解的事实，且用户愿意补充 | 一个具体、当下可回答的问题 | 20-60 字 |
| 讲解 | 用户要求听讲，或需要一个概念、例子 | 清楚的解释、例子与必要边界 | 120-250 字 |
| 比较 | 当前解释过于单一，或用户需要理解选项差异 | 两种以上可能性及区分它们的依据 | 120-250 字 |
| 建议 | 用户请求建议，材料足以支持有限建议 | 建议、依据、关键条件和不确定处 | 100-220 字 |
| 收束 | 用户想结束，或当前信息只支持有限结论 | 已明确之处，必要时说明仍不知道什么 | 不超过约 80 字 |

每轮只有一个主动作，最多附一个可选问题。长度是默认阅读预算，不能为了截断而丢失关键条件；用户要求详细解释时可以扩展。点击结束始终在本地完成，不依赖模型先生成收束。

两轮补材料预算按问题用途计算，所有主动作共用；讲解或比较后附带的补材料问题同样计数。达到上限后不得通过更换主动作继续索要当天材料。计数以问题首次实际展示并确认记录为准，重复打开同一轮不重复计数；用户主动选择继续回忆才开启新的预算段。

### 5.2 必须优先遵循的用户选择

- “直接讲给我听”：不以再回答一个问题作为教学前提。
- “想不起来”：允许立刻换到教材；默认两轮补材料上限后不继续索要经历。
- “这个我知道”：调整深度、换内容或结束，不重复相同教材。
- “你理解错了”：以用户修正为当前材料，旧解释保留为历史，不继续当作事实。
- “现在不想继续”：停止追问，不生成后续作业。

对自然语言的理解由模型负责；对应的明确 UI 操作可以直接改变状态。不能只根据关键词给用户诊断动机、性格或能力。

### 5.3 产品级输入输出契约

输入至少包含：入口类型、用户本次明确选择、当前会话必要轮次、引用材料原文与 ID、可用教材目录、已提出的补材料问题次数、输出协议版本。教材目录包含 ID、版本、标题、主题、中心观点摘要和适用情境，不能只发送模型无法理解的 ID。已经选中并正在讨论的教材发送全文。

本轮选择新教材时，模型按目录选条目，客户端呈现该版本预先审核的全文；不要求模型凭目录重写教材。用户继续讨论时再把全文纳入下一轮，避免为一次选择串行请求多次。

输出包含：一种主动作、可呈现正文、最多一个问题、实际引用的来源 ID、可选的教材 ID，以及允许的后续操作建议。草稿生成另有明确请求类型，返回草稿正文和依据来源，不混入用户未经确认的资产。

客户端验证协议、来源是否属于此次输入、教材是否在候选中、操作是否在白名单。模型输出不直接执行保存为理解、创建验证、发通知或改成长记录等副作用。

“举个例子”等教学按钮是请求意图，不作为用户自身表达解锁理解草稿。长会话裁剪不得保留已被纠正的旧事实却移除纠正；最新原话与所引用材料的有效纠正一起纳入本轮来源。

协议或来源无效时，当前轮显示失败并允许重试；不呈现有问题的结果，也不生成本地假点拨。完整 JSON Schema、迁移字段和 Swift 类型由技术设计表达，但必须实现这里确定的产品行为。

## 6. 保存、草稿与状态转换

### 6.1 保存规则（FR-05、FR-07）

| 对象 | 何时保存 | 确认与修改规则 |
| --- | --- | --- |
| 未提交文字 | 编辑中定期保存；切页、退后台和请求前同步保存 | 可继续编辑；未持久化时不得声称已保存 |
| 用户已提交文字 | 请求模型之前 | 保留原文；修正作为新表达关联原文 |
| 已呈现的模型回应 | 呈现前或在同一提交边界保存 | 记录该轮和来源；不得只展示而完全无法恢复 |
| 静态教材 | 首次呈现时保存条目 ID、版本及可恢复内容 | 内容包更新后仍能还原用户当时看到的版本 |
| AI 理解草稿 | 用户主动请求且生成成功时 | 标记未确认，不计为用户认可的观点 |
| 用户确认理解 | 点击“保存为我的理解”事务成功时 | 保留确认文本和来源；修改保留版本关系，允许删除 |
| 反馈 | 用户主动选择时 | 可以不填；不能改变原文或自动证明成长 |

空白进入后立即离开，不创建空交流。已展示教材的零输入会话有实际内容，应当可回看。用户提交的文字和已呈现内容自动保存的规则，在首次输入附近或数据设置中应可发现；不要求为每条消息另行确认。

### 6.2 状态契约

| 当前状态 | 用户或系统事件 | 下一状态与持久化结果 |
| --- | --- | --- |
| 空白 | 仅打开再退出 | 返回首页，不新建空记录 |
| 编辑中 | 提交文字 | 保存成功后进入请求中；失败停留并保留输入 |
| 编辑中 / 可交流 | 阅读教材 | 教材和来源保存后成为可交流记录 |
| 请求中 | 有效回应 | 保存并进入可交流 |
| 请求中 | 超时、取消、协议失败 | 保留已提交内容，进入可恢复状态 |
| 可交流 | 主动整理理解 | 发起草稿请求，成功后进入草稿编辑 |
| 草稿编辑 | 确认保存 | 事务成功后回到可交流；失败保留编辑内容 |
| 有内容的任意状态 | 到这里 | 取消在途请求并持久化为已结束，不等待总结 |
| 有内容的任意状态 | 退后台、关闭页面或开始另一件事 | 取消在途请求，保存为暂停，允许恢复 |
| 已结束 / 暂停 | 继续这件事 | 恢复原会话上下文，追加轮次 |

一次只允许一个活动请求。取消、退出或新会话开始后到达的旧响应不能覆盖当前内容。状态名称是实现契约，不需要直接显示给用户。

保存失败是“立即退出”的明确例外：先取消在途请求，保留当前可见内容，提供“重试保存”和“放弃未保存改动并退出”。放弃需要一次确认，且不删除此前已保存的内容。这样用户可以离开，但系统不能声称未落盘的内容在进程被关闭后仍可恢复。退后台时若写入失败，已保存部分保持可恢复，重新前台时报告尚未保存的状态；不得用成功提示掩盖失败。

### 6.3 删除与历史兼容

删除交流需要明确确认，删除其草稿、确认理解和相关反馈，并让派生引用失效。旧 vNext 来源对象不随一个新导师会话被误删；如果旧记录仍被引用，按既有数据治理规则处理并说明影响。

包含被删除会话原文的请求副本与派生摘要也应清理或脱敏；允许保留不含原文且不能重建私人内容的故障统计。用户要求删除的数据不能只从列表隐藏后继续被模型引用。

旧 `SingleNudgeSession` 按原有字段和轮次链回看，不强制重新生成成新格式。新旧版本来源、请求和输出应可区分。迁移失败时恢复原库和原有可用路径，不把历史 AI 解释改写成用户确认结论。

## 7. 异常、性能与成本约束

| 情况 | 必须提供的行为 |
| --- | --- |
| 没有 API Key | 内置内容和历史可读；发送在线请求前提示配置，保存输入，允许改为阅读 |
| 网络离线 | 静态内容、草稿、历史和编辑可用；在线交流明确不可用，不伪装成功 |
| 请求超过 10 秒 | 保持取消与退出可用，说明仍在等待，不重复提交 |
| 流式请求连续 600 秒没有输出内容 | 取消并提供本轮重试；持续内容延长等待。断流预览仅本页内存可复制，不冒充已保存回应 |
| 连续点击提交 | 同轮只发出一个请求，保存一份用户输入 |
| 保存失败 | 输入和结果保留在当前可见状态，提示失败；修复前不显示成功、不继续依赖持久化的下一步 |
| 内容缺失或版本无效 | 不显示空白页或伪造内容，提供可用条目、历史或退出 |
| 长文本与大字号 | 可滚动、可展开，关键操作不被键盘、底部栏或长正文遮挡 |

前台导师单次用户动作默认只发起一次模型请求；语义回复与教材选择尽量在同一次请求完成。格式失败和网络失败由用户明确重试，不静默连发多次。阅读、回看、确认已编辑文本和结束不需要模型请求。

本地操作的交互反馈目标为 100ms 内，内置教材首次可读目标为 1 秒内；在线请求记录实际耗时，不把这些设计预算当作已测结果。2026-10-22 导师回应与整理理解采用 SSE 与正文预览：首个输出前从提交开始最多等 600 秒，有非空输出文本则续期 600 秒无内容截止，持续生成不受旧总时限打断。十秒提示等待，用户可返回取消；一次 HTTP、不自动重发。心跳不续期，网络及供应商仍可失败。预览未通过完整结果校验，断流只能本页复制；用户输入与既有会话仍保存。未带进度通道的内部请求保留旧普通 API 30 秒／Responses 120 秒总预算；历史失败见[原专项验收](qa/2026-10-21-mentor-criteria/README.md)，新证据见[流式验收](qa/2026-10-22-mentor-streaming/README.md)。

## 9. 验收与价值验证（FR-08）

### 9.1 可执行验收矩阵

| 编号 | 前置条件与动作 | 可观察的通过结果 |
| --- | --- | --- |
| T01 | 新安装、无 Key、无历史，点击听讲 | 1 秒目标内显示 L01 全文与教学示例标识；网络请求数为 0 |
| T02 | 无材料点击回看，再选择想不起来 | 不要求输入文字，直接进入教材；不创建空白日记 |
| T03 | 输入“今天一直在开发”，连续两轮仍无片段 | 不出现第三轮索要当天材料的问题，可听讲或结束 |
| T04 | 从单条闪念开始 | 原文带入且来源正确，不要求补第二条，不覆盖闪念 |
| T05 | 用户要求直接解释或修正理解 | 回应类型和上下文随之变化，未重复原错误判断 |
| T06 | 同日重复进入听讲，再点击换一个 | 首次恢复旧内容；主动换题后展示另一条，旧内容可回看 |
| T07 | 标记不相关或已知道，重启后再次使用 | 会话级主题排除与持久条目排除分别符合规则 |

| T09 | 只读后结束，未回答也未评分 | 立即退出、保存阅读记录；没有理解结论、任务或成长贡献 |
| T10 | AI 草稿中含用户未表达的经历 | 来源与语义评估判为失败，不允许把它当作通过的理解输出 |
| T11 | 编辑草稿、取消、确认及再次修改 | 草稿与确认理解状态明确，确认后内容可恢复，来源与版本正确 |
| T12 | 提交后关闭页面、取消或新开交流，旧响应晚到 | 新交流与旧输入均不被旧结果覆盖 |
| T13 | 网络超时或多次点击提交 | 流式在 600 秒无内容截止后进入可恢复态，持续内容可续期；一次动作没有重复请求或重复记录 |
| T14 | 在请求前、结果保存或确认理解时注入写入失败，再尝试结束 | 不显示保存成功；可重试保存或确认放弃未保存改动，旧已保存内容不丢失 |
| T15 | 结束后重启、从最近列表继续、跨日再进入 | 恢复当时教材版本和上下文，追加轮次且不覆盖历史 |
| T16 | 删除导师会话，随后查看导出与旧 vNext 记录 | 新会话及派生内容按规则删除，旧来源未被误删 |
| T17 | 打开旧单问会话与迁移失败的数据库 | 原文可回看；失败恢复路径可用，无强制模型改写 |
| T18 | 小屏、大字号、键盘、深色、VoiceOver | 主要内容与结束动作可访问，无遮挡或关键截断 |

T05、T10 等语义质量项需要人工与模型输出评估；协议、数据和 UI 自动化不能独立证明它们通过。验证沿用项目规定的模拟器和设备范围，不在本文中改变测试设备政策。

### 9.2 试用口径

入口尝试：用户点击三个开始动作之一，或从闪念进入；模型未配置、早退和失败也保留为尝试，不为提高指标而剔除。主路径分类按首次入口固定，切换另外记录。

流程结束、内容已读、理解已确认与具体获益分别记录。具体获益需要用户自愿说明看清或改变了什么，或后续给出复用事实；“已保存”“已读”和模型自评不能代替。

至少记录：入口、是否有材料、内容和协议版本、首份完整内容呈现时间、请求耗时、退出阶段、可选反馈、是否确认理解，以及自愿提供的获益描述。统计不复制原始私人材料到分析日志，语义复核使用用户允许的材料和来源 ID。

### 9.3 分开的两个门槛

**交付门槛：** 首发教材完整审核；T01-T18 适用项通过并有证据；相关既有保存、迁移和来源回链回归通过。通过后可进入试用，不能因此宣布用户价值成立。

**继续投入门槛：** 约 14 天探索性使用中，至少记录 12 次真实尝试，至少 6 次为无准备启动；带题与导师供题两类各至少 4 次尝试，并各出现至少 3 个能说清具体帮助的案例。保留全部未获益、退出和未反馈结果，以每类总尝试数报告，不能只展示成功样例。

这是本版暂定的早期判断线，不是统计显著性或普遍留存标准。自然使用未达到样本条件时记为证据不足，可以延长观察或邀请相近用户；不能要求用户制造问题或每天补作业。

未通过时按原因决定：启动难则改入口；没有片段则改回忆支架；内容空泛则改教材；重复或误解则改介入协议；保存与返回难则改流程。任何可靠性严重问题先修复，不能用增长功能补偿。

| 工作包 | 必须交付的具体结果 | 依赖 |

产品负责人负责内容取舍、编辑审核和语义评估；设计负责页面与状态可用性；开发负责协议、持久化和实现；验证负责人负责场景证据。个人项目可由同一人承担多个角色，但交付结果不能省略。

WP-01 与 WP-02 可并行，WP-03 与 WP-04 在数据契约稳定后可并行。只有当用户能从开始走到结束并再次找到内容时，才算一个可试用版本；入口按钮或接口单独完成不等于产品完成。

本 PRD 决定首版体验、规则、范围和验收。配套系统设计与接口契约给出 JSON Schema、暂定迁移号、类与接口、视图拆分和验证边界；功能拆解将其映射到 19 项交付。实施前核对最新工程状态，内部组织可调整，不能由技术任务重新决定用户第一次看到什么、无法回答怎么办或结束后留下什么。

## 11. 变更与后续阶段

首版发布前如调整默认内容、24 份规模、14 天去重、补材料问题上限或协议请求预算，需要说明理由并更新对应规则、验收项和试用记录中的版本。

后续能力按真实证据展开：需要自然回访时验证可选提醒；反复重述背景时接入经允许的相关历史；实际产生验证需求时缩短验证路径；有跨场景复用证据时再表达长期能力变化。

本版回答的是“用户没有准备也能获得一次具体帮助，并能把这次帮助找回来”。长期导师效果应在此基础上继续验证，不能因首版交付而提前宣称成立。
