# 明思 PRD

## Overview

明思是一款面向个人知识工作者的 iOS 思维训练 App。它把每日输入、结构化整理、深度追问、明日任务、次日验证和长期原则沉淀连接成一个闭环。

MVP 采用 SwiftUI iPhone 原生实现，直接调用 GLM，用户自带 API Key，并使用本地优先存储。

核心闭环：

```text
Clarify -> Challenge -> Choose -> Act -> Calibrate
```

## Goals

- 降低每天复盘的输入成本。
- 将原始输入转化成结构化卡片。
- 通过透镜和追问训练更深思考，而不是只做摘要。
- 生成一个高价值的明日主线任务。
- 次日验证任务是否完成以及实际价值。
- 将可复用的结论沉淀为原则资产。
- 形成长期可回看的历史证据链。

## Target User

首版只服务一个 alpha 用户：

- 忙碌的个人知识工作者。
- 需要在工作环境中避免输入敏感原始资料。
- 愿意用 10-15 分钟做一次完整的日常思考训练。
- 想提升清晰度、判断力、执行力和校准能力。

## User Journey

### First-Time Setup

用户创建一个思考档案：

- 选择主要训练目标：清晰度、价值判断、执行可靠性、项目判断、反思深度。
- 确认隐私边界：不输入公司文档、代码、客户名、内部标识或敏感数据。
- 输入 GLM API Key，存入 Keychain。
- 创建一个或多个抽象项目。
- 完成五项成长指标的基线自评。
- 选择默认训练模式，建议 Standard。

输出：

- 思考档案。
- 初始项目列表。
- 默认周训练重点。

### Daily Reflection

用户开始一天的训练：

1. 输入原始文本。
2. 选择 Quick / Standard / Deep 模式，或使用默认推荐模式。
3. 系统整理出结构化卡片。
4. 用户修正、合并、删除或标记敏感卡片。
5. 选择或接受推荐的思考透镜。
6. 回答至少一个深度问题。
7. 确认明日主线任务和最多两个次要任务。
8. 接受或保存一个可复用的原则候选。

输出：

- 确认后的每日卡片。
- 透镜回答。
- 明日任务。
- 原则候选。

### Next-Day Verification

第二天，App 先验证昨天的主线任务：

- 完成状态：已完成、部分完成、未完成。
- 实际价值：高、中、低、不明确。
- 如果未完成或价值偏低，记录原因。

输出：

- 执行记录。
- 校准记录。

### Weekly Calibration

每周生成一次校准报告：

- 最有价值的动作。
- 最低价值的时间消耗。
- 重复出现的阻塞。
- 重复出现的思考模式。
- 下周训练重点。

输出：

- 周度模式摘要。
- 推荐的训练透镜。

### Monthly Growth Review

每月生成一次前后对照报告：

- 更清晰的任务定义例子。
- 执行可靠性的变化。
- 判断校准趋势。
- 重复未解决的薄弱点。
- 下月训练建议。

输出：

- 月度成长报告。

### Historical Review

用户可以回看历史会话，并将其作为成长证据。

历史体验需要回答：

- 某一天发生了什么？
- AI 整理出了什么卡片？
- 选择了什么透镜？
- 生成了什么主线任务？
- 任务是否完成，结果是否有价值？
- 哪些历史例子证明成长，哪些例子说明问题重复出现？

输出：

- 可搜索、可过滤的历史记录。
- 与 Growth 和 Projects 联动的证据链接。

## Core Features

### Daily Input

要求：

- 大文本输入区域。
- 自动保存。
- 明显的隐私提醒。
- Organize 操作触发卡片提取。
- 原始输入始终可编辑。
- 输入内容支持 Quick / Standard / Deep 三种模式。

### Card Organization

AI 将原始输入转成结构化卡片。

卡片类型：

- Fact
- Problem
- Decision
- Risk
- Idea
- Communication
- Task

要求：

- 卡片可编辑。
- 卡片可删除。
- 卡片可合并。
- 卡片可标记重要。
- 卡片可标记为敏感并从后续模型调用中排除。
- 最终追问只能基于用户确认后的卡片。

### Thinking Lenses

MVP 透镜：

- First Principles
- Occam's Razor
- Opposing View
- Opportunity Cost
- Leverage Analysis
- Evidence Check
- Execution Bias Check

要求：

- AI 在卡片整理后推荐一到两个透镜。
- 用户可接受推荐或手动选择。
- 选择的透镜至少生成 3 个问题。
- 用户必须回答至少一个问题后，才能生成明日任务。

### Quick / Standard / Deep

三种模式用于控制流程长度和追问深度：

- Quick：快速整理和收敛，只保留最少问题。
- Standard：默认模式，完整走一遍卡片、透镜、任务和原则候选。
- Deep：用于周复盘或重要事件，问题更多，校准更深。

要求：

- 模式必须在数据里可记录。
- Prompt 依据模式选择不同深度。
- 模式切换不影响底层数据结构。

### Tomorrow Quest

App 生成轻量游戏化的任务集。

任务类型：

- Main Quest
- Side Quest
- Observation Quest

要求：

- 至少一个主线任务。
- 最多两个次要任务。
- 最多一个观察任务。
- 每个任务都包含：
  - 为什么重要。
  - 完成标准。
  - 预期阻力。
  - 事后反思问题。
- 主线任务必须由用户确认后才激活。

### Verification

App 在开始新一天训练前，先验证昨天的主线任务。

要求：

- 询问完成状态。
- 询问实际价值。
- 如果未完成或价值偏低，记录原因。
- 将结果用于校准和成长指标。

### History

历史存储并展示过去的每日输入、卡片、透镜、答案、任务和验证记录。

要求：

- 按日期展示记录列表。
- 展示日循环状态：draft、organized、confirmed、quested、verified、incomplete。
- 支持单日详情。
- 原始输入默认折叠。
- 用户确认后的卡片可筛选。
- 任务和验证结果必须与源记录链接。
- Growth 报告必须能深链到历史证据。
- Project 页面可以显示相关历史记录。
- 用户可以从历史卡片创建新的后续任务。

History 是证据层，不是普通归档。

### Principle Library

最小原则库用于沉淀可复用的行动准则。

要求：

- 每次日常训练结束后，AI 可建议 0-1 条原则候选。
- 用户可保存、修改或忽略。
- 原则记录需要保留来源、适用场景和验证状态。
- 后续版本可扩展为原则对照和能力训练，但 MVP 只做最小沉淀。

### Growth Metrics

App 追踪五个趋势指标：

- Clarity：用户是否能清楚表达真实问题。
- Value Judgment：是否能选择更高价值的动作。
- Execution Reliability：是否能完成确认过的主线任务。
- Calibration：预期结果与实际结果是否逐步对齐。
- Reflection Depth：是否能识别假设、风险和重复模式。

要求：

- 指标基于证据，而不是主观打分。
- 指标需要能链接到历史记录。

### Settings

设置项包括：

- GLM API Key。
- 默认训练模式。
- 隐私边界说明。
- 数据导出与清除。
- 本地通知开关。
- 主题和字体密度。

## AI Boundaries

- AI 负责整理、推荐、追问和校准建议。
- 用户负责确认、取舍、验证和原则采纳。
- AI 不能要求用户上传原始敏感资料。
- AI 输出必须可追踪到 prompt 版本和模型版本。

## Non-Goals

MVP 不做：

- 服务端代理。
- 账号体系。
- App Store 发布流程。
- 自研语音识别。
- Apple 日历/提醒事项同步。
- 完整角色卡系统。
- 外部框架包市场。
- Mirror Cards。
- 能力图谱。
- Schema 动态 UI。
- 复杂动画。

## Acceptance Criteria

MVP 完成时，用户能够：

- 输入一次完整的日常反思。
- 得到结构化卡片。
- 选择透镜并回答至少一个问题。
- 获得一个可执行的明日主线任务。
- 第二天完成验证。
- 保存一条原则候选。
- 在历史里找到完整证据链。
