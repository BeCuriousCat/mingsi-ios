## 1. 文档定位与使用方式

本总纲回答明思为谁服务、何时值得使用、导师应该提供什么帮助、如何组织体验，以及后续开发如何判断取舍。它是拆分设计方案、功能 PRD 和开发任务的上位依据，不是一次性实现全部功能的交付清单。

本文件单独不足以作为首版开发与验收依据。首版的页面行为、完整流程、内容选择、导师协议、保存状态、异常预算和验收，现由 [首版完整产品方案](mingsi-mentor-m1-prd.md) 明确。总纲回答长期方向，首版 PRD 决定当前具体交付；首版细节与本文原则性描述有差异时，以首版 PRD 的明确取舍为准。

本次迭代的三个关键决定：用户不必先知道想什么；导师能够直接提供讲解和新视角；表达、验证与长期成长按需发生。首期要交付一段从无准备开始、获得具体帮助、可以自由结束的完整体验。

阅读建议：产品与设计先读第 2-8 节；开发拆解重点读第 9-11、15 节；验收与试用按第 12-13 节执行。

## 2. 问题依据

### 2.1 用户已经表达的需要（归纳）

> 忙碌是常态，每天都在开发或干活，不知道什么时候该使用明思。觉得应该有输出和回顾，但不知道如何整理，也不知道有什么值得反思。希望明思作为思想导师，提供新的输入和点拨。

这暴露了当前体验的一个前提：用户需要先发现值得想的事情，再把材料交给明思。对于持续忙碌的人，发现材料、找到角度、组织表达，本身就是需要帮助的工作。

当前需要解决的困难包括：

- 启动困难：不知道什么情况下值得打开明思。
- 材料困难：普通的一天里，想不起有什么值得回看。
- 视角困难：即使能说出做了什么，也不知道还能怎样理解。
- 表达困难：有模糊体会，但无法组织成自己的话。
- 延续困难：当时有所启发，下一次做事时却用不上。

### 2.2 产品需要修正的假设

开发、修复问题、沟通和做取舍，本身就是输出。明思不把“今天没有写总结”解释为没有成长，也不要求每天发生重大事件或产生深刻结论。

产品要帮助用户从日常经历中获得理解，也要在用户没有材料时提供新的观察角度。每天回看是可选择的节奏，不是道德要求；没有新发现、只读一点内容、休息或跳过，都是正常结果。

## 3. 产品定义与核心能力

### 3.1 一句话定位

明思是一位融入日常的思考导师：帮助忙碌的人找到值得想的事情，获得新的视角，表达自己的理解，并在现实中逐步校准判断。

### 3.2 最重要的能力

理解用户当前的处境和思考过程，选择此刻最有帮助的一次介入，并让这次帮助有机会在下一次生活或工作中发挥作用。

这项能力有两个互相补充的方向：

- 用户带着事情来：明思帮助听清、澄清、解释、取舍和验证。
- 用户没有事情可说：明思帮助回忆一个片段，或主动提供一个有价值的输入。

长期价值是用户逐渐能够独立观察、表达和判断。明思可以支持用户有依据的原判断；不能为了显示导师能力，强行找错或制造认知变化。

### 3.3 导师角色

导师可以提问，也可以解释、示范、比较、提出建议和承认不知道。建议需要说明依据、适用条件和不确定之处，决定仍由用户作出。

导师对具体表达和思考动作提出意见，不根据一句话给用户贴人格、能力、动机或情绪标签。没有写出的背景应先确认，不能直接当作没有想到的证明。

## 4. 用户、时机与价值承诺

### 4.1 初始目标用户

先服务持续投入开发、创作或知识工作的人，产品拥有者作为首位试用者。用户可能忙碌、输入零散、回看经验少，也可能已经会反思但需要新视角。不能预设他们都愿意每天完成 10-15 分钟的训练。

开发工作是首批验证场景，不是永久内容边界。后续输入可以涉及沟通、审美、生活观察和用户主动选择的其他方向。

### 4.2 使用时机

| 时机 | 用户需要 | 明思应提供的开始方式 |
| --- | --- | --- |
| 工作告一段落、收工或个人选定的空闲时间 | 不知道今天有什么可回看 | 从一个容易回忆的片段开始 |
| 遇到一个具体卡点 | 想理清事情或作出选择 | 直接接住当前输入 |
| 没有问题，只想得到一点启发 | 新观点、案例或观察方法 | 无需先写材料的短输入 |
| 想起一个零散念头 | 先记下，或顺手想一步 | 轻量保存，可直接继续思考 |
| 有了新的实际结果 | 看看原先的理解是否成立 | 继续原来的事情并对照证据 |

默认建议只建立一个日常时机，例如收工后。首版不需要用户安排早、中、晚三套流程，也不依赖系统自动识别其工作状态。

### 4.3 一次使用的承诺

一次使用可以帮助用户达成以下任意一项，不要求全部完成：

- 回忆并看清一个原先忽略的具体片段。
- 理解一个新的区别、观点或方法。
- 把模糊的想法用自己的话表达清楚。
- 确认、修正一个判断，或明确还缺什么信息。
- 找到一个愿意尝试的小动作或观察方向。

首版体验目标为轻量回看约 2-5 分钟、单份新输入约 1-2 分钟。这是待验证的设计目标，不是强制时长或已达到的性能承诺。用户主动深入时可以延长，任何阶段都可以结束。

## 5. 核心体验模型

```text
用户打开明思
  -> 有具体事情：直接理清
  -> 不知从哪说：带着回看一个片段
  -> 暂无材料或只想听：提供一个新的输入
  -> 根据需要解释、示范、提问或比较
  -> 可以直接结束，也可以表达自己的理解
  -> 自愿留下记录；有条件时自愿留下现实验证
  -> 下一次遇到相关事情时继续使用
```

这是可选择、可回退的体验关系，不是一条所有人必须走完的状态机。允许从回看切换到听讲，也允许新输入让用户想起自己的经历后继续讨论。

两条主路径必须同时成立：

- 当场帮助：进入 -> 获得一个有用的起点或解释 -> 可以离开。
- 持续学习：理解 -> 自愿表达或尝试 -> 后来得到证据 -> 更新或复用理解。

结束、阅读、跳过、保存、验证和获得成长证据是不同事件，不得互相替代。

## 6. 核心产品要求

### MENTOR-01：零材料也能开始

- 用户没有历史、没有今日记录、没有项目，也能开始一次导师体验。
- 默认提供“带我回看”的清晰动作，同时保留直接输入和“给我一个新视角”的选择。这些是同一体验的开始方式，不是三套独立产品。
- 不知道说什么的用户不应被要求先填写“今日收获、主要问题、训练目标”。
- 用户不输入自由文本，也能直接读到一个完整的讲解或案例。不能仅用一个新的问题代替零输入路径。
- 首次使用不以创建项目、能力自评、选择透镜、开启通知或授权工作记录为前置条件。

### MENTOR-02：从经历中发现材料

- 从容易回忆的事实开始，例如“你今天最后在处理什么”，避免一开始要求评价整天或总结收获。
- 根据用户表达，一次追问一个具体细节，寻找取舍、意外、反复、预期变化或顺利完成的片段。
- 明思提出“这个片段可能值得看”的理由，允许用户纠正、换一个或表示没有特别之处。
- 如果用户仍然想不起来，提供一个具体例子帮助回忆，或切到新输入；不得反复索要当天材料。
- 可以从一条闪念直接开始。现有“至少两条才能按日聚合”不应成为导师交流的门槛。
- 不自动把用户普通的一天描述成存在深层问题，也不将忙碌解释为效率低、焦虑或逃避。

### MENTOR-03：提供值得听的新输入

输入的目标是让用户多理解一个区别、看见一种可能或获得一个观察方法。一次围绕一个中心意思展开，不同时列出多套框架。

一份完整输入通常包含：具体观点、短例子、适用边界；可以附加一个自愿尝试的观察。用户不回答问题，也能读懂并结束。

可使用的内容来源：

| 来源 | 使用要求 |
| --- | --- |
| 经过编辑的小型内容库 | 有主题、适用情境、例子、边界、版本与来源类型；首版无需内容平台 |
| 明确标注的教学示例 | 可以用于解释概念；不能冒充真实研究、他人经历或用户亲历 |
| 可核实的外部材料 | 显示可访问来源；不能编造作者、研究结论或引文 |
| 用户允许使用的历史片段 | 显示关联来源，区分过去事实与本轮解释 |

选择输入时考虑用户明确选择的关注方向、当前材料、已经看过的内容、所需精力和具体适用性。有历史时才谈历史关联，没有历史时提供通用但具体的内容，不伪装成个性化洞察。

用户可以表达“不相关、已知道、换一个、现在没精力”。当次选择需要立即生效，后续推荐减少重复；不能因为一次忽略就断定用户长期没有兴趣。

首版使用有限、经过检查的内容集合，不建设无限信息流。内容选择与解释质量应先于内容数量扩张。

### MENTOR-04：根据需要教学与点拨

| 用户状态 | 合适的介入 | 应避免的行为 |
| --- | --- | --- |
| 事实或对象不清 | 一个具体澄清问题 | 直接判断用户能力不足 |
| 不理解某个概念 | 简短讲解与示范 | 继续让用户猜答案 |
| 已有单一解释 | 比较替代解释及其证据 | 为反对而反对 |
| 需要取舍且背景充分 | 有依据的建议与取舍说明 | 永远只问问题或替用户决定 |
| 只是想听一点内容 | 提供可独立理解的输入 | 强制答题后才展示价值 |
| 已经想清楚或精力有限 | 收束、确认或结束 | 为凑流程继续训练 |

“一次只推进一点”是交互原则；“每次只能返回一个问句”不再是整个导师产品的统一要求。改动现有点拨协议时，应通过新版本和相应用例验证，保留旧轮次原文与来源。

### MENTOR-05：帮助表达，自愿留下

- 根据用户已经表达的内容，帮助整理一段可编辑的理解草稿。只有实际出现的信息才进入草稿。
- 可参考“发生了什么、原先怎样想、现在怎样理解、仍不确定什么”，但不要求每次填满四栏。
- 用户没有表达判断变化时，不生成“刚刚发生的成长”或补造前后差异。
- 会话和用户输入按本地保存规则保留；AI 生成的草稿应标记为草稿，只有用户确认后才作为其认可的结论或长期经验。
- 允许只留一个问题、一句话、一个观察方向，也允许不整理。反馈、保存草稿或创建验证都不能成为退出的门槛。
- 不自动发布、分享，不自动创建待办、项目、原则或成长贡献。

### MENTOR-06：延续、验证与复用

- 用户能在统一回看中找到导师交流、闪念、自己的表达和实际结果，并选择“继续想这件事”。
- 一件事可以跨日期延续，不要求每天重新组织全部背景；历史原文与新解释分别保留。
- 初期只使用少量直接相关的历史。关联可查看、可纠正，不能将全部历史默认发给模型。
- 只有材料包含可以被未来事实检验的判断或预期，且用户愿意时，才建议留下验证。
- 验证草案承接当前交流，确认“当时怎样判断、观察什么、何时或在什么条件下回来”。不要求重新走完整的今日整理流程。
- 回来后对照原判断和实际结果，允许支持、调整、推翻或仍不确定。完成动作不等于证明判断正确，良好结果也可能受其他因素影响。
- 有证据时再提出可复用经验，并说明适用条件；用户可以修正或拒绝，不生成永久人格标签。

### MENTOR-07：主动但有分寸

主动性首先发生在 App 内：用户打开时，明思能提供一个开始的理由，而不是等待一份准备好的材料。

- 系统通知单独选择开启，首版默认不开启。开启后，由用户选择一个合适的时间窗口，每日最多一次常规导师邀请；这是一项上限，不是发送目标。
- 已有一次有意义的交流、用户暂停提醒或表示没精力时，不继续催促。忽略不触发当天追问，也不产生补做欠账。
- 一次开始只突出一个起点；当天已经读过的内容可以继续回看，不通过反复刷新制造新任务。
- 用户主动请求新内容不受常规邀请上限限制，但无需使用无限滚动承载。
- 通知不显示敏感经历或能力判断。拒绝通知、日历和其他数据权限，不影响核心体验。
- 已有生活奇遇可以作为可选生活探索能力；与导师输入共享必要的提醒频率控制，避免不同功能轮流打断用户。

## 7. 代表性体验与结束条件

以下是设计示例，不是真实使用证据。文案可以调整，行为边界应保留。

### 场景 A：忙了一天，没什么可总结

1. 用户选择“带我回看”，只说“今天一直在开发”。
2. 明思从最后一个具体工作片段切入；用户提到首页改了几轮。
3. 明思了解最近一次修改的依据，而不是立即归因于完美主义或需求不清。
4. 根据补充情况，讲解一个可能有用的区别，例如“完成改动”和“改善使用”的检查方式。
5. 用户可以留下自己对这次修改的理解，也可以只听到这里。

成功标准：用户不需要预先总结一天，就能围绕一个具体片段获得帮助。若修改本身已有清楚依据，也应允许确认现有做法并结束。

### 场景 B：没有任何记录，只想获得一点新输入

1. 新用户没有输入文本，选择“给我一个新视角”。
2. 明思展示一个具体短案例及讲解，例如怎样从第一次使用者的角度观察一个熟悉工具。
3. 展示必要的来源或示例标识，说明该角度适用的情况。
4. 用户可以直接结束、换一个，或说起自己的经历。

成功标准：零历史、零文本输入时也获得完整内容；不要求先记录两条闪念、建项目或回答测试题。

### 场景 C：今天很顺利，也不想继续思考

用户认为今天没有特别之处，或者表示很累。明思接受这一状态，允许结束；如用户愿意，可以保存一句事实。不能编出隐患、强制总结收获或降低成长评价。

### 场景 D：想法有了，但表达不出来

用户零散讲出自己的理解。明思先确认意思，再给出短草稿；用户可以修改、保存或保留为未确认内容。输出不得加入用户没说过的因果、感受或决定。

### 场景 E：用户已经懂了，或者认为导师理解错了

用户说“这个我知道”“你理解错了”或“直接讲给我听”。明思调整解释深度、纠正理解或直接教学，不重复同一追问，也不把分歧解释成用户抗拒成长。

## 8. 信息架构与界面方向

### 8.1 首页

首页的首要任务是让用户立即开始。保留一个主要开始动作；直接输入、获得新输入、继续最近一件事是清晰但次级的选择。

首页不同时展开模式库、透镜库、成长指标、项目统计、任务列表和生活奇遇。到期验证可提示，但不能阻塞新的交流。

新用户不看复杂能力仪表盘。首次体验先展示可获得的实际帮助；关注方向和提醒时间在需要时再选择。

### 8.2 交流页

正文是核心工作区，使用原生文字、输入和导航行为。短讲解与对话可以自然衔接，不将每一句话或每一个字段都包装成独立卡片。

当前事情、引用来源、用户回答和 AI 草稿应可辨认。主要操作随当前需要变化，始终提供可发现的结束方式。反馈可以跳过，不与继续、退出或查看内容绑定。

### 8.3 回看

下一阶段建议以“明思”和“回看”作为两个主要区域，设置使用次级入口。项目作为长期议题、成长作为证据和周期总结进入回看，原有资料仍可访问。

该结构是目标方向，首期可以先在 Today 中收敛主入口；不以一次改完所有 Tab 作为导师体验上线条件。迁移时保留原有历史链接、搜索与返回路径。

回看重点展示“当时怎样想、后来发生什么、现在怎样理解”，并提供继续入口。没有变化证据时，只展示实际记录。

### 8.4 原生质量

沿用现有设计规范，优先保证 Dynamic Type、VoiceOver、深色模式、键盘避让、44pt 触控目标和小屏长文本。默认、空、加载、失败、恢复、取消和权限拒绝均应可用。

## 9. 模型、内容与数据边界

### 9.1 职责划分

中央 LLM 负责理解语义、选择介入、生成讲解、判断哪些历史或内容相关，以及提出基于材料的解释。本地代码负责权限、可用内容、来源约束、保存、次数与时间控制、撤销、失败恢复和界面状态。

优先扩展现有中央决策与 PromptRun 机制。不得仅凭关键词命中，直接宣称用户有某种思维缺陷或已经成长。经过编辑的静态示例可以直接浏览，但必须明确其内容性质，不能伪装成模型刚刚作出的个人判断。

### 9.2 每轮可使用的上下文

- 当前用户明确选择的开始方式、输入和必要的本轮交流。
- 用户主动设置的关注方向、当次精力偏好或内容偏好。
- 少量、直接相关且允许引用的历史来源。
- 当前可用的内容条目及其来源类型、适用条件和版本。
- 防止重复推荐所需的近期呈现与反馈记录。

新用户无需先建立画像。首期不依赖后台读取代码、工时、日历、聊天记录或设备活动；未来连接器另立方案。已有其他功能的授权不自动扩大为导师读取权限。

### 9.3 必须保留的事实区别

| 内容 | 产品如何对待 |
| --- | --- |
| 用户原话或选择的素材 | 来源事实，保留原文和日期 |
| 模型解释、建议或关联 | 可纠正的生成内容，不能冒充用户结论 |
| 用户修改或认可后的表达 | 用户确认的理解，保留与原材料的关联 |
| 教学案例或外部知识 | 标识来源类型，不计为用户经历 |
| 后来的真实结果 | 校准依据，不能由 AI 补造 |
| 能力变化推测 | 需要来源和适用范围，证据不足时不作断言 |

具体存储模型由技术方案决定，不要求按表格新建同名实体。优先复用 `SingleNudgeSession`、`CaptureFragment`、现有 Verification / Evidence / Project 和 PromptRun；需要扩展时明确版本、兼容与回链关系。

用户应能查看和管理保存内容、导出和删除自己的数据、纠正历史关联。删除或撤回材料后，相关引用和派生摘要应同步失效或更新，不能继续作为推荐依据。

### 9.4 失败与首次配置

模型未配置、网络失败或输出不可用时，保留输入和已经呈现的内容，允许重试当前轮、结束和稍后恢复。取消后到达的结果不能覆盖新的交流；保存失败不能显示保存成功。

内部验证阶段可以保留 BYOK。未配置模型时应明确可读的配置入口；已随应用提供的编辑示例可继续阅读，但不能冒充在线教学结果。面向普通消费者时，需要单独解决首次价值之前的配置门槛；订阅、服务端和账号不是本轮导师验证的前置工作。

## 11. 分阶段推进

### M0：准备首条可验证体验

目标：把本总纲拆为足够小、可开发和可观察的方案。

交付：核心旅程设计、导师介入协议、初始内容集合、代表性评估案例和试用记录格式。明确版本迁移、保存与来源边界，列清新行为对旧单问协议的影响。

通过条件：用示例走查本总纲场景 A-E，全部有可用的开始和结束路径；确认无材料路径不依赖额外权限、自由文本或几天的积累。走查结果仅算设计验证。

### M1：无准备也能获得一次帮助

范围：MENTOR-01 至 MENTOR-05 的最小完整体验，同时保留用户带题的即时点拨；包含基本保存、恢复、内容来源、可选反馈和最小最近交流回看。具体交付以 [首版完整产品方案](mingsi-mentor-m1-prd.md) 为准。

用户可以直接提问、被带着回看，也可以零输入读到完整的新内容；交流中可以教学与点拨，最后自愿留下自己的表达。

使用时机先通过首页与明确的日常场景建立。M1 不新增系统定时邀请；后续验证提醒时另立切片并满足 MENTOR-07，不将其作为首版依赖。

通过条件：代表性场景、失败恢复和相关回归通过；完成首轮真实试用，能够记录具体获益与放弃原因。不能只凭生成成功或 UI 测试通过宣布导师有效。

### M2：让帮助在下一次继续生效

范围：MENTOR-06，统一回看、少量相关历史和直接承接的轻量验证；逐步收敛信息架构。

通过条件：真实用户能够从旧记录继续同一件事；能用实际结果调整理解；来源正确且可纠正。没有历史材料时，M1 的全部入口仍然成立。

### M3：根据真实反馈发展长期学习

范围：根据观察扩展内容、调整推荐节奏、按证据呈现周期变化；必要时再接入更多经用户选择的素材来源。

通过条件：观察到新情境下的复用案例，能够区分“在提示下完成”和“独立运用”；内容与提醒没有持续增加负担。不能用阅读量、使用天数或完成次数替代这一证据。

上述阶段按用户价值排序，暂不承诺固定开发工期。每个阶段都应形成可以单独试用的产品切片。

## 12. 成功标准与试用设计

### 12.1 核心观察

主要观察：一周内发生多少次有具体获益依据的使用，以及用户在下一次合适时机是否愿意自然回来。扩大用户规模后，可进一步观察获得这类帮助的人数与占比。

“具体获益”可以是用户说明新理解了什么、表达清楚了什么、调整或确认了哪个判断，或后来在现实中复用了什么。模型自述“本轮有帮助”、保存按钮点击和一句“点到了”都不足以单独证明能力提升。

只读与跳过是有效结束，但不能自动计入已获益；用户后来说明某份输入有帮助时，可以补充关联。对一次没有帮助的使用，也应允许如实记录。

### 12.2 试用方法

先由产品拥有者进行约 14 天的探索性使用，明确记录哪些天忙碌、没有材料、没有打开或只读。根据问题修正后，再邀请约 3-5 位相近目标用户验证可理解性与重复价值。这些样本只能支持早期判断，不代表普遍留存或产品市场匹配已经成立。

按开始方式分别分析结果，不把“带题点拨”和“零素材输入”的平均表现混为一谈。关键记录包括：

- 启动机会、实际打开原因与没打开的原因；不自动把未打开算成失败。
- 是否需要提前组织材料，在哪一步停下或放弃。
- 哪段输入或哪次介入有用，用户能否具体说明。
- 不相关、已知道、太抽象、误解、重复或增加负担的情况。
- 是否愿意在下次类似时机回来，有无后来复用或验证的证据。

收集行为和自愿反馈应遵循最小化原则；统计不需要复制原始私人材料或记录到分析日志。自动保存的 PromptRun 来源仍用于必要的质量定位。

### 12.3 初始体验目标

以下是首轮试用的暂定判断线，调整时记录原因，不能回填或美化结果：

| 观察项 | 初始目标或判断方式 |
| --- | --- |
| 零素材可开始 | 新输入路径在规定的冷启动场景中均无需自由文本、历史或额外权限；属于硬性产品要求 |
| 启动负担 | 首批至少 10 次真实尝试中，至少 8 次无需先整理长材料即可开始；覆盖至少 5 次无准备尝试 |
| 回看成本 | 愿意轻量回看的会话，中位用时约 2-5 分钟；同时记录退出与负担，避免通过强制截短达标 |
| 具体价值 | 两种主路径都应出现可描述的获益案例；用户带题有效不能掩盖导师供题无效 |
| 再次使用 | 观察合适时机下的主动回访原因与未回访原因，先建立基线，不强制每日使用 |
| 现实复用 | M2 起收集后来使用旧理解或修正判断的具体实例，不要求每轮都有验证 |
| 可信与可恢复 | 无输入丢失、来源串线、虚构用户经历或将失败伪装为成功；发现即修复并复验 |

如果只在催促下使用、反复找不到具体获益，或新输入大多被认为空泛，应回到介入方式和内容选择调整。此时不通过增加成长指标、推送频率或更多入口补偿。

### 12.4 导师质量评估

评估问题是否抓住当下需要、解释是否具体、事实是否可靠、是否尊重用户表达，以及能否适时结束。使用真实反馈补充案例，比较不同 Prompt / 内容版本，每次尽量只改变一个主要因素。

可将同一材料下的明思体验与同一模型的普通对话做盲评，检查产品设计是否带来额外价值。格式解析、字数限制和固定测试只能保证协议与部分行为，不能代替对教学和判断质量的评估。

## 13. 验收场景清单

| 编号 | 输入或条件 | 必须表现 |
| --- | --- | --- |
| A01 | 全新用户，零历史、零文本输入 | 直接获得可独立理解的新输入，不引回必填表单 |
| A02 | “今天一直在开发，没什么可总结” | 从具体片段切入；想不起来时可转讲解，不预设心理问题 |
| A03 | 只有一条闪念 | 可以围绕这条交流，不要求补第二条 |
| A04 | “直接讲给我听” | 提供解释或示范，不用持续反问替代教学 |
| A05 | “这个我知道 / 不相关” | 当次可换角度或结束，后续减少重复 |
| A06 | “你理解错了” | 修正上下文，不继续沿错误归因生成结论 |
| A07 | “今天很好 / 很累 / 不想整理” | 允许结束，不制造缺陷、作业或成长扣分 |
| A08 | 用户没有报告想法变化 | 不生成虚构的前后差异或成长证据 |
| A09 | 用户只读、未评分、未保存草稿 | 可以正常结束，状态不伪装为已获益或已验证 |
| A10 | 模型缺失、失败、取消、保存失败、重启 | 材料和来源可恢复，状态真实，无迟到结果覆盖 |
| A11 | 外部事实与教学示例混合 | 明确来源类型，不把示例当作用户经历 |
| A12 | 用户主动选择现实验证 | 承接当前判断生成可编辑草案，不强迫重走完整训练 |
| A13 | 用户拒绝权限或暂停提醒 | 核心入口可用，无追加催促，其他邀请遵守总频率约束 |
| A14 | 继续旧记录或撤回历史关联 | 只使用允许的正确来源；撤回后不继续引用 |
| A15 | 在新情境下主动采用旧方法 | 可以记录复用事实，但不由一次结果推断全面能力提升 |

M1 至少覆盖 A01-A11，以及 A13 中拒绝权限不影响使用的部分。启用通知时完整覆盖 A13；M2 增加 A12、A14；M3 增加 A15 的长期观察。相关既有保存、迁移和证据回链回归继续执行。

## 14. 暂不扩大投入的方向

首轮导师价值验证之前，不扩大以下工作：

- 无限资讯流、课程市场、庞大方法库和复杂能力测评。
- 新成长分数、排行榜、连续打卡、每日产出配额与补做机制。
- 全量工作记录接入、后台活动推断和复杂自动触发。
- 账号同步、多 Provider、团队协作及商业化基础设施。
- 完整项目管理、社交分享和自动发布。
- 为配合新定位而重做全部页面、品牌图标或已有存储结构。

生活奇遇、完整训练、项目和成长可以保留，其扩展应有真实需求或证据支持，不能挤占首条导师体验的验证。

## 15. 后续子 PRD 与开发任务的约束

建议依序拆出：

1. 无准备启动与首页核心旅程，覆盖 MENTOR-01、MENTOR-02。
2. 导师输入内容与多种介入协议，覆盖 MENTOR-03、MENTOR-04。
3. 交流保存、表达草稿与自由结束，覆盖 MENTOR-05。
4. 真实试用、质量反馈与版本比较，覆盖第 12、13 节。
5. 统一回看、历史延续与轻量验证，覆盖 MENTOR-06。
6. 可选邀请与频率治理，覆盖 MENTOR-07。

前三项共同组成 M1 的可用体验，不能只实现新的入口名称就宣布阶段完成。第 4 项随 M1 同步准备和执行。

每份子 PRD 必须写明：对应要求编号、用户场景、当前与目标行为、最小完整流程、正常结束与失败恢复、来源和保存边界、明确不做的内容、验收用例及实际验证方式。技术任务应链接对应子 PRD，不以数据库表、模型调用数量或页面数量作为交付目标。

首版的内容清单、导师输出的产品契约、导航范围、同会话历史与撤回、提醒范围、模型接入方式已经在 [首版完整产品方案](mingsi-mentor-m1-prd.md) 中决定。后续子 PRD 可细化技术与布局，不应将这些决定重新留白；跨主题记忆、全局导航迁移及面向普通消费者的模型服务在相应阶段另作决策。

评审任何新功能时，先检查它是否帮助用户更容易开始、获得具体的新理解、表达自己的想法，或在下一次事情中用上。如果关联不清楚，应推迟到核心体验取得使用证据之后。
