## 2026-09-11：F03 暂停与回应事务

新增 suspendSession，把请求取消、草稿版本检查和暂停/结束状态一起提交；新增 commitResponse，以请求和会话归属检查阻止无主、跨会话、取消后的回应写回。相同已提交回应重放返回原条目，内容冲突拒绝。v56 用请求结果关联表和组合外键保存一对一归属。该表随所属会话/请求删除，后续 F15 必须将其纳入导出白名单。

MentorPersistenceTests 共 9 项通过，包括请求结果关联插入失败的回滚、暂停事务失败回滚、暂停后恢复仍拒绝旧请求、删除后回调与重复回调。测试运行于 MingSi Dev 模拟器。回应方法目前只是存储边界，JSON 对象检查不能替代 F09 的完整协议和动态来源验证；审计前置条件、修订代次、内存取消及 UI 行为尚需实现。

## 2026-09-11：F03 草稿修订与显式恢复

草稿保存拒绝负修订、旧修订和同修订不同内容；相同内容重放不修改活动时间。暂停/结束后新的防抖保存被拒绝，结束记录也不能被迟到暂停操作改写。resumeSession 作为显式继续命令恢复编辑状态，保留已取消请求的终态。

新增草稿重放/冲突及关闭后迟到写入测试，包含结束后显式继续并编辑的路径。这里仅保证数据库事务的状态约束；跨“恢复后”的旧 UI 操作仍需后续 request_epoch / 生命周期代次和 Store 取消机制共同防护，不宣称这些机制已完成。

## 2026-09-11：F03 语义纠正与请求代次

v57 新增会话 semantic_revision / request_epoch、请求 expected_revision / epoch、条目 supersedes_item_id 和纠正命令记录。correctUserItem 对同会话用户原话追加纠正，保留旧条目，拒绝同一原话分叉纠正；请求取消、修订与代次递增在同一事务完成。纠正命令重放幂等，暂停也递增请求代次，新请求保存当时修订与代次。回应落库再次比较，不能仅依赖网络取消。

MentorPersistenceTests 共 13 项在 MingSi Dev 通过。新增证据覆盖原文保留、重复纠正、纠正后旧回应拒绝、错误重置请求状态后的修订检查、新修订请求正常提交，以及最终写入失败时整笔纠正和请求取消回滚。mentor_corrections 属于会话数据，F15 导出与删除治理须包含该表。

未完成边界：上下文装配必须使用最新纠正及匹配的快照；Store 需持有并验证操作代次，不能从本次存储测试推断 UI 迟到操作已全面防护。来源、严格审计、呈现确认与完整生命周期仍需继续实施。
