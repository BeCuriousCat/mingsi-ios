## 1. 使用方式

每项功能都包含用户需要、预期增益、实现边界、缺陷与验收。P0 表示 M1 对外试用交付不可缺少，不表示必须同时开发。S / M / L 是相对实现规模，非工期承诺；教材的编辑审核另外计算投入。

技术能力的价值通过它保护的用户行为体现。例如数据库事务不直接产生启发，但决定用户的表达能否找回。不能因为它没有独立页面而省略，也不能因为写了基础设施就宣称导师价值成立。

## 3. 功能细项

### F01 教材结构、资源与校验

- 实用性与增益：零输入、零 Key 时立即有完整内容可读；用结构和版本保证更新后仍然知道当时读了什么。
- 实现与产物：实现 LessonCatalog，加载内置 JSON 内容包；使用配套 [内容 Schema](contracts/mentor-m1/lesson-pack.schema.json)，校验 24 个唯一 ID、编辑序号、六组分布、L01 / L02、来源与版本；接入 Bundle 资源和测试。
- 缺陷与控制：只有标题没有正文、资源未加入 target、相同版本悄悄改内容、虚构出处都要拒绝。坏条目不能导致全页空白；发布包不得依靠降级状态过关。
- 验收与依赖：T01、T08、T15；X08。本项交付资源机制与校验，完整内容由 F02 完成，二者不能互相代替。

### F02 首发内容与审核

- 实用性与增益：给用户一个能理解的区别或方法，减少面对空输入框的准备成本；价值由具体获益反馈判断。
- 实现与产物：完成 PRD 六组各四份的全文，标明教学示例或可核实来源、适用边界、版本和审核结果；将 PRD 两份规格示例纳入对应首发条目。
- 缺陷与控制：避免泛泛鼓励、把工作效率作为唯一主题、把观点写成普遍规律、附加必答题。长度只作阅读预算，不机械凑字。
- 验收与依赖：F01；T01、T10 的来源和教学相关项；产品逐条审核后进入内容包。24 份数量达标不能证明使用价值。

### F03 导师模型与事务仓储

- 实用性与增益：用户原话、教材、模型建议和确认理解不混淆，关闭后仍能找回，重复点击不产生重复记录。
- 实现与产物：落地系统设计中的六类权威表、约束、索引及 submitTurn、commitResponse、presentLesson、confirmUnderstanding、pause / finish 等命令；统一 Clock / Calendar 注入。
- 缺陷与控制：防止多个 save 造成半提交、UUID 来源串线、JSON 内只有关系而无真实所有权、按日期覆盖会话。事务失败必须抛错给 Store。
- 验收与依赖：T11-T15；X01、X06。每个组合命令都做写入故障和幂等验证，证明全部提交或全部回滚。

### F04 迁移与回退

- 实用性与增益：已有使用记录在升级失败时仍然可用，避免新导师上线成本由老用户的数据承担。
- 实现与产物：核对最新迁移后增加暂定 v53；增加当前库备份、导师迁移上限与能力门禁；复用文件租约处理 App 和 CaptureIntent 的并发打开。
- 缺陷与控制：不能恢复陈旧 pre-vnext、直接复制未处理 WAL 的文件、静默切到临时内存，或在新数据已写入后恢复旧快照。
- 验收与依赖：F03；T17；X03、X11。分别演练新库、v52 真形状夹具、旧链数据、迁移各失败点及成功开放写入后的功能禁用。

### F05 三种开始方式与页面整合

- 实用性与增益：用户有问题、没有材料、只想听讲时都能直接开始；首页不要求理解项目、模式和透镜。
- 实现与产物：独立 MentorFeatureStore 与五类页面；Today 主动作按未结束交流切换，保留两个次级开始方式、单条闪念入口、最近三次与全部列表；旧今日整理继续可达。
- 缺陷与控制：避免三个入口成为三套不互通的数据，避免有旧会话就禁止新事情；不新增第六个 Tab，不隐藏已有资料。
- 验收与依赖：F03；T01、T02、T04、T09。默认、新用户、暂停、有草稿、存储不可用与未配 Key 都要有明确动作。

### F06 离线听讲与阅读恢复

- 实用性与增益：用户不提交自由文本也能读到完整讲解，退出再回来不丢位置。
- 实现与产物：默认 L01、编辑顺序、教材快照、同日入口恢复、主动换题、已读详情与耗尽状态；静态阅读请求数为零；首屏不加载全部历史。
- 缺陷与控制：同日恢复不能重新显示已明确拒绝的内容；有话题时转为阅读或换题也不调用模型；不能将重复打开算作新推荐或新收获；Bundle 更新后历史读取原版本。
- 验收与依赖：F01、F03、F05；T01、T06、T08、T09、T15；X07、X08。阅读位置在 Dynamic Type 变化时至少恢复到原段落。

### F07 去重与反馈

- 实用性与增益：减少已知道、刚看过和当前不相关的内容，用户的一次反馈能够产生可解释的变化。
- 实现与产物：同会话排除、14 个自然日已呈现排除、会话主题排除、跨会话已知道和撤销机制；模型只能从最终合法候选中选题。
- 缺陷与控制：不因一次不相关变成永久偏好；版本升级不绕过去重；删除记录后不留下无来源的隐藏画像；反馈不能等同能力评价。
- 验收与依赖：F06；T06-T08；X07。覆盖午夜、时区变化、同条多来源反馈、重置与删除后从剩余事实重建。

### F08 草稿、自由结束与恢复

- 实用性与增益：用户能够在忙碌中暂停，重新进入时不用重述；可以离开而不被强制总结和评分。
- 实现与产物：500ms 防抖与关键边界 flush、修订号、暂停 / 结束 / 切换、进程重启后的 interrupted 状态、本地保存失败后的重试或放弃确认。
- 缺陷与控制：不沿用“先显示已收好再排队保存”；慢写不得覆盖新输入；已有响应仅保存失败时不重新请求模型。
- 验收与依赖：F03、F05；T09、T12-T15；X01。明确进程终止前未落盘部分无法恢复，不用成功提示遮掩。

### F09 上下文与响应契约

- 实用性与增益：每轮依据用户正在说的事情提供帮助，避免过多历史导致偏题、隐私范围扩大或等待变长。
- 实现与产物：新增 mentorRespond / mentorDraftUnderstanding，组装当前会话、教材目录或全文、来源集合与预算；实现两个响应 Schema 的解析和动态约束。
- 缺陷与控制：不能只给模型教材 ID；不能把来源检查等同事实正确；超限不得静默截断最新输入，保留原材料时必须保留最新纠正；引用内容中的指令不能越过系统协议。
- 验收与依赖：F01、F03；T03、T05、T10；X10、X13、X16。检查实际发送集合、格式反例和非法引用，语义质量交给 F18。

### F10 请求策略与严格审计

- 实用性与增益：在线交流等待有边界，一次提交不被静默重复计费，已结束或删除的请求不能重新写回。
- 实现与产物：请求级一次 HTTP、禁用 JSON 降级重发、按协议 30 秒／Responses 120 秒总截止、10 秒等待提示、前台教练占用、URLSession 取消、所有权审计与 epoch / semantic_revision 检查。
- 缺陷与控制：只把 maxRetryAttempts 改成 0 仍有隐藏格式重发；只取消 UI token 无法阻止 tracing 写入；只用 TaskGroup 等不合作的子任务可能无法按时恢复界面。
- 验收与依赖：F03；T12-T14；X02、X04、X05、X14。URLProtocol 统计实际 HTTP 次数，模拟拒绝取消的客户端和审计写入失败。

### F11 引导与五类介入

- 实用性与增益：帮用户从具体片段开始，并在需要教学时直接解释；用户不会被困在重复补材料中。
- 实现与产物：回看首轮的具体回忆入口（已配模型时由导师自动提供，未配模型时保留本地输入）、所有主动作共用的两次 AI 补材料上限、question_purpose 与用户明确继续的预算段、五种主动作与显式意图处理、从听讲自然转入个人事情。
- 缺陷与控制：模型不能将没写出的材料视作能力缺陷；到了上限不能用本地模板假装 AI 讲解；用户纠正后不能继续引用旧错误解释作事实。
- 验收与依赖：F08、F09、F10；T02-T05、T09；X06、X16。测试讲解、比较、建议、收束及用户明确不想继续。

### F12 理解草稿与确认版本

- 实用性与增益：用户已有体会时减少组织表达的困难，同时保留对自己结论的控制。
- 实现与产物：主动生成草稿、用户自己写一句、编辑 / 取消 / 确认、确认后的新版本、理解组删除；没有用户表达时不生成 AI 的“我的收获”。
- 缺陷与控制：教材原理、AI 建议和用户理解不能混为一谈；“举个例子”等教学按钮仅记录意图，不作为个人表达解锁草稿；确认与再次编辑不能覆盖先前证据；生成失败不丢已写文本。
- 验收与依赖：F08、F09、F10；T10、T11、T14。确认与编辑后的确认均零网络请求；语义反例不能只靠来源 ID 校验。

### F13 最近交流与继续这件事

- 实用性与增益：首版留下的东西马上可找回，在相关事情上继续交流时减少重新整理背景。
- 实现与产物：最近三条、20 条游标分页、详情来源、恢复位置、同会话追加轮次、用户选择旧片段补入当前上下文；标题使用原文预览或教材标题。
- 缺陷与控制：不按 dayKey 限制续接；不为标题额外调用模型；不把全部历史加载到首屏或 Prompt；“已结束”的阅读恢复不自动开启新请求。
- 验收与依赖：F03、F05、F08；T15；X13。覆盖同时间排序、多页、跨日、长链、来源失效及从详情返回原列表位置。

### F14 旧单次点拨兼容

- 实用性与增益：旧用户的点拨和表达仍然能看、能继续，不需要重新生成历史或维护重复列表。
- 实现与产物：LegacyNudgeAdapter 整链读取、只读投影、首次继续的唯一包装、旧根与新会话列表去重，以及损坏 lineage 的明确降级。
- 缺陷与控制：不能把 diagnosis 迁成用户确认理解；孤立父引用和环不能造成无限遍历；删除包装后旧根不能以幽灵记录再次出现。
- 验收与依赖：F04、F13；T15-T17。旧 input、question、answer、两个 PromptRun 与时间都保持可追溯。

### F15 删除、备份与导出

- 实用性与增益：用户能够真正控制私人表达，导出能完整迁出数据，删除不会误伤旧事项。
- 实现与产物：基于结构化所有权的事务删除、严格审计拒绝迟到写入、请求副本与摘要清理、导出表登记、临时文件清理、应用管理备份作废或重建。
- 缺陷与控制：不能只隐藏列表、不清理 response_json；不能只删现有请求而放任 late upsert；不能用 LIKE 猜关联；不能恢复已删内容的旧备份。
- 验收与依赖：F04、F10、F13、F14；T16、T17；X02、X12。覆盖共享借用来源、旧链所有权、删除失败回滚和应用外副本不在控制范围。

### F16 设置衔接

- 实用性与增益：配置模型后能回到刚才的事情，用户也能撤销已知道的反馈，而无需清空全部记录。
- 实现与产物：设置返回定位、Keychain 变化刷新、在途请求取消、旧请求实际模型快照、already_known 重置、保留静态阅读。
- 缺陷与控制：不能配置前先丢掉输入；刷新服务不能让旧请求进入新会话；反馈重置不绕过独立的 14 天呈现排除。
- 验收与依赖：F07、F08、F10；T01、T07、T12。密钥不进入数据库快照、日志、Schema 示例或导出。

### F17 原生质量与性能

- 实用性与增益：忙碌、小屏、大字号或使用辅助功能的用户都能顺利阅读、表达和结束。
- 实现与产物：沿用 DS，校验明暗外观、Dynamic Type、VoiceOver、键盘、返回、44pt 目标；测量本地响应和教材加载，长列表不全量读取审计正文。
- 缺陷与控制：文字不被固定底部按钮挡住，语义状态不只靠颜色，长内容不挤掉结束；不为新风格重写整个设计系统。
- 验收与依赖：F05、F06、F12、F13；T18，T01 性能部分。复用项目固定模拟器执行规范，不自行增加日常测试设备。

### F18 观测、语义评估与真实价值

- 实用性与增益：让后续迭代知道究竟是哪种帮助有效，而不是只看到调用量和完成数。
- 实现与产物：mentor_usage_events 记录不含正文的入口尝试、实际呈现、结束原因和草稿确认；具体获益归属于会话反馈；建立各介入类型的正反案例和约 14 天试用记录模板。空白退出仍保留尝试，重新进入使用新的 attempt_id。
- 缺陷与控制：不能删除未配 Key、失败、早退样本来美化结果；没有反馈标 unknown；模型自评和只读均不自动计为成长。私人获益正文留在用户允许的记录中，不写通用日志。
- 验收与依赖：F03、F06、F11、F12；FR-08、T05、T10。按初始入口和实际切换分别分析，报告各类总尝试数与具体获益证据。

### F19 集成验收与阶段决策

- 实用性与增益：完整使用链路通过后才扩大试用，避免功能单测都绿但用户仍无法走完。
- 实现与产物：T01-T18 与 X01-X16 的适用证据、相关原有回归、迁移演练、教材审核清单、发布 / 回退检查和明确的试用结论。
- 缺陷与控制：协议验证不等于模型语义正确；样例演示不等于真实使用；功能交付通过不等于长期导师价值成立。
- 验收与依赖：总表所列依赖全部具备。技术交付和继续投入分别作决定，不用新增通知、评分或内容市场补偿核心无效。

## 4. 交付顺序与并行边界

### 4.1 可试用增量

| 增量 | 用户能完成什么 | 主要功能 | 仍不代表什么 |
| --- | --- | --- | --- |
| A：基础与离线旅程 | 无 Key 听讲、换题、结束，并在列表找回 | F01-F08、F13 的相关部分 | 不是完整 M1；没有在线导师与理解生成 |
| B：在线导师与表达 | 带着材料或没有准备地交流，生成并确认自己的表达 | F09-F12、F16 | 还需完成旧数据、删除和全链路质量验证 |

## 6. 实现后的增益如何评估

| 预期增益 | 对应功能 | 证据形式 | 不能替代它的指标 |
| --- | --- | --- | --- |
| 无准备也能开始 | F05、F06、F11 | 无材料入口的真实尝试、启动成本、退出原因 | 首页访问量 |
| 新输入能打开一个角度 | F02、F07、F11 | 用户能具体说清理解了什么，或后来引用某份教材 | 阅读时长、教材数量 |
| 表达更容易留下 | F08、F12 | 原话到确认理解的对应、修改负担、恢复成功 | AI 草稿生成量 |
| 旧事情不用重复讲 | F13、F14 | 同会话继续时是否少了重复准备，来源是否正确 | 历史条数 |
| 使用可靠可控 | F03、F04、F10、F15、F17 | 故障注入、取消、删除、导出、可访问性与性能实测 | 单个 build 成功 |
| 后续投入有依据 | F18、F19 | 按入口分别报告总尝试、未知反馈、获益实例和未获益原因 | 综合满意率或模型自评 |

初期不设置无法证明的能力提升百分比。PRD 的两类路径各至少 3 个具体获益案例只是继续探索的初始判断线；应同时报告分母和失败例，避免只展示成功故事。

## 7. 子任务交付格式与验收责任

每次实施以一个或一组有依赖关系的 F 编号为范围，记录：修改文件、落地行为、对应 SD / FR / T / X、迁移影响、测试证据、剩余限制和预期增益如何观察。若修改产品行为，同时更新 PRD；若仅调整类型或文件组织，更新系统设计即可。

无需为本文重新创建一批“待写更详细 PRD”的任务。可以直接从 F01 和 F03 开始技术实施，同时完成 F02 内容；最终在 F19 汇总实际证据。当前任务只交付系分和拆解，不将未来实现状态标为完成。
