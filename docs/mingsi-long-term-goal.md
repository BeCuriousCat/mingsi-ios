# 明思长期 Goal 与验收契约

制定日期：2026-10-23。状态：**进行中；尚未完成真实价值验证与普通用户安装交付。**

## 1. 我们最终要做成什么

**让明思成为可信、低负担的日常思考导师：人在没有准备时也能获得具体帮助，在下一次生活或工作中能独立运用，并且其他人能够安装、理解和持续使用这个开源产品。**

长期希望改善的是观察、表达和判断能力：分清事实与推测，说清自己的标准，理解不同处境，权衡代价，在现实反馈后修正判断。透镜、教材、人生指南、语音和多轮交流都是实现这些价值的手段；数量增加本身不代表进展。

这个愿景没有永久完成的一天。因此当前总 Goal 有一个可结束的范围：**交付首个通过真实使用、后续复用与公开安装验证的明思版本。** 完成本期只能说明早期价值成立，不能声称普遍提升认知能力或达到产品市场匹配。

本契约落实[导师产品总纲](mingsi-mentor-product-prd.md)第 11–14 节与[M1 PRD](mingsi-mentor-m1-prd.md)第 9 节；保留它们已有的试用门槛，补充后续复用、公开交付与统计要求。历史修复是子里程碑，不等同于总 Goal 完成。新增数字是本期暂定决策线，不是经过研究验证的行业标准。

## 2. 如何判断正在变好

主要价值指标是：**每个观察周，有多少次真实使用产生了用户能具体说明的帮助，其中多少在后来被独立复用。** 同时报告总尝试数、未获益、未反馈与退出，不能只数成功案例。

三种证据分开记录：

1. 交互成功：打开、输入、得到响应、保存、重新找到；证明流程能用。
2. 当次获益：用户能说清自己理解、表达或判断的具体变化；证明这次帮助有价值。确认原来的判断也可计入，但要说明确认依据。
3. 后续复用：在另一真实事件中使用了此前的方法或理解，并说明如何使用；证明出现早期迁移。必须区分看到提示后使用和没有提示时独立使用。

不以使用时长、日活、打卡、读完条数、透镜数量或测试数为主要价值目标。只读、休息与跳过可以正常结束，不能自动算获益，也不算个人失败。

## 3. 统计与证据规则

- **入口尝试**：点击开始点拨、带着回看、听一个新视角或从闪念进入一次。首次入口固定分类；切换单独记录，不重分到表现更好的类别。无 Key、报错、早退也保留。
- **两类主路径**：用户带题；导师供题（无准备回看或新输入）。报告细分入口，不能让带题有效掩盖供题无效。
- **具体获益案例**：用户自愿说明原先困惑、哪段帮助有用、形成的理解或判断。AI 可按标准整理证据，不能代用户认定获益；单独的“有用”、点击保存或模型自评不算。
- **独立复用**：另一日期的另一真实事件，在明思本次提醒前已经使用旧方法；用户可描述原事件、当前事件和具体应用。仅重读、复述术语、照抄建议或被提示后回答不计入独立复用。
- **统计窗口**：产品拥有者先自然试用约 14 天；修复后 3–5 位目标用户各约 14 天；复用观察覆盖参与者初次使用后的至少 4 周。可以重叠，不能跳过修复或压缩观察。预计至少 6–8 个日历周，属于观察安排，不是发布日期承诺。
- **版本绑定**：记录构建、Prompt、内容版本与服务配置标识，不记 Key。可靠性重大修改后复验受影响路径；语义重大修改后分版本统计，不拼接成一个版本的通过率。
- **不改分母**：未反馈按未反馈保留，不自行推断有用或无用；显示“明确获益数 / 全部尝试数”及反馈覆盖率。补测有新编号，原失败不覆盖。未发送请求不算通过。
- **不制造样本**：自然使用不够则记证据不足，延长或扩展自愿试用；不要求每天制造问题、补作业。合成案例、AI 扮演用户不进入真实使用统计。
- **资料最小化**：统计只需匿名 ID、日期、入口、版本、结果和自愿提供的简短说明。私人原文、音频、Key 不进入公开证据；引用需用户允许。默认不增加外部遥测。
- **冻结口径**：v1 契约作为后续采样依据。调整阈值需记录日期、原因、旧值、新值；已有数据按原口径保留，另起新窗口，不回填美化。

## 5. 如何逐步推进

### M0：把现状和缺口说清楚

产物：本契约、需求到证据的台账、真实试用记录模板、隐私与已知限制说明。按 T01–T18/A01–A15 将已有证据标为满足、部分、未测；不要把历史不同版本的通过混成一次全量通过。

阶段结束：每个指标都有口径、当前状态、证据和下一动作，已有最高优先级风险进入待办。此阶段完成不代表产品有效。

### M1：在手机上可靠地获得一次帮助

先补真实可用性：闪念草稿生命周期、麦克风授权/拒绝/中断/重录、快捷入口冷暖启动、SSE 等待/取消/断流、保存重开、大字号与 VoiceOver。优先处理会让人丢内容或以为已经成功的问题，再优化间距和文案。

透镜与 Prompt 围绕明确思考动作优化：事实与推测、标准与取舍、换位理解、可逆性与反馈。案例覆盖直接要答案、没有材料、纠正误解、已经知道、停止与风险；预先分开发集与留出集，不把语义质量缩成字段/关键词检查。

完成适用交付门槛后开展拥有者约 14 天真实使用，满足 G2/G4。同期验证 G1/G3/G8 的适用部分；发现严重可靠性问题先修复。当前工程已经具备部分基础，**现在应先补证据缺口和真实路径，而非继续无界增加透镜。**

### M2：帮助能找回来，也能继续用

统一已有记录的回看与继续入口，相关历史只在用户允许下使用，可查看来源并撤回；现实结果可以修正旧判断，不自动制造成长。根据真实反馈决定最小改动，不先造庞大记忆或 Agent 框架。

修复拥有者试用暴露的问题后，准备 3–5 人试用包、可选反馈和盲评材料。达到 G5/G7，并收集 G6 的复用证据。没有自然复用时回查帮助是否具体、检索是否困难、方法是否适合；不以提醒强迫用户制造复用。

### M3：验证独立复用并交付公开版本

完成至少 4 周的后续观察，核对 G6/G8。给出负面案例与适用人群，明确哪些帮助能复用、哪些只是当场感觉不错。按反馈整理核心页面与内容，避免为展示更多能力增加负担。

公开交付作为贯穿阶段的工作：保持源码、许可、安装与 API 文档可用；本地准备签名分发所需清单与候选包，实际发布遵循用户授权和 Apple 账号/渠道条件。G9/G10 通过后，发布与验收绑定同一候选版本。账号或审核未就绪时明确记外部依赖，不能把源码链接当作普通用户安装验收。

阶段结束：G1–G10 全部达到、证据索引可复查、无未解决硬门槛问题，产品拥有者确认真实获益与交付边界。本期总 Goal 才能标完成；之后另设下一周期，不追溯改写本期结论。

## 6. 明确边界

- 本期服务愿意自配模型的 iOS 26+ 个人用户；首先在拥有者真实设备成立，再在少量相近用户成立。“公开使用”包括安装路径，不能默认人人有 Mac/Xcode。
- 模型辅助思考，决定权属于用户；不做心理诊断、医疗/法律/财务专业结论，不根据一句话判断人格或能力，不保证每轮必须发现问题。
- 每日人生指南是可忽略的资料入口；场景相关建议是可选卡片。避免增加“索取随机建议”任务，不把推送或阅读量算获益。
- 不新增连续打卡、成长总分、排行榜、作业配额；不为增加指标强制用户验证或强制每天回来。
- 本期不扩展账号云同步、社交、团队、商业化、无限资讯流、后台全量材料接入、跨平台重写。若真实证据表明它们阻塞主 Goal，再单独论证取舍。
- 不把引入 Pi/Agent Loop 本身设为目标。先确认 SSE、取消、状态恢复和请求预算；只有真实任务需要多步工具调用时才评估框架。
- 2026-10-23 已补闪念正文与待确认识别文本的本机草稿恢复，见[专项证据](qa/2026-10-23-capture-draft/README.md)。只承诺成功提交到本机数据库的文字，不保留原始音频；其他输入框未扩展跨进程转写恢复。写入失败必须提示，不能靠缩小文案掩盖实际丢失；真机强退与系统语音仍待验收。
- 不默认外传私人内容，不公开真人原文，不携带作者 Key/订阅分发。AI 编辑/审读如实标注，不能替代真实用户反馈或冒充独立专家。
- AI 可以准备、开发、验证、汇总；真实感受、现实复用和签名账号条件由真实参与者/平台提供。不会代填真人数据或擅自联系试用者。

## 7. 已完成的基础与当前差距

[2026-10-22 核心体验优化](qa/2026-10-22-core-goal/README.md)属于 M1 的工程子里程碑：最终单元 1509 通过、24 显式跳过、0 失败，闪念关闭保护与字号修复已有模拟器证据；UI 联合结果与最后专项结果分开报告。31 次请求的 28 次完整接纳和 3 次服务失败保留在同一版本下。

## 8. 总 Goal 完成与失败处理

**完成条件是 G1–G10 全部满足且产品拥有者确认本期结论，不能仅以代码写完、测试全绿或 AI 认为有用结束。** 发布前最后修改需复验受影响路径，不能把旧构建证据全部搬过来。

数据/安全/来源硬门槛失败：停止该切片交付，保留失败，修复并复验。

价值或迁移门槛失败：分析无帮助、误解、太抽象、重复、负担或无法找到的原因，一次修改一个主要变量，再开展有界观察；不靠加功能、改分母或降低标准宣布完成。

样本、真人反馈、账号或分发条件不足：标记证据不足或外部依赖，继续独立可做的准备；总 Goal 保持未完成。若用户决定停止、缩小或转向，记录真实决策与未达成指标，不称原目标已达成。
