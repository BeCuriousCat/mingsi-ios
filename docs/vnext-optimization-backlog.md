# vNext 优化审计与小步推进

更新时间：2026-08-20

这份清单用于把“感觉可以优化”变成可验证的小步。每一步只改一个主要问题，先跑自动化和模拟器验收，再决定是否继续。

## 当前基线

- 截至 2026-08-20，`MingSiTests` 已验证为 974 项通过、0 项失败、1 项跳过；此前 Prompt 文档断言漂移已修正。
- iPhone 17 模拟器的 Today、History、Projects、Growth、Settings 截图已覆盖；当前没有发现明显的安全区、动态字体或底部导航遮挡。
- 完整 `MingSiUITests` 已于 2026-08-20 在固定 iPhone 17 模拟器串行通过：55 项通过、0 项失败。回归前发现一条支线 fixture 仍断言旧素材标题，已同步为稳定素材库标题并完成聚焦复验；再次执行时保留数 GB 临时构建与测试空间。
- `CentralLLMDecisionCenter` 已作为生产模型流量的统一入口。vNext 正式运行中，Today、Coach、Guidance、Growth、Projects、Side Quest 的实质判断均通过该入口；无 Key 或模型失败不会静默升级为本地判断。
- vNext 生产中的历史成长判断也遵循同一不变量：中央 LLM 未产出报告前，不自动持久化本地启发式 `MetricSnapshot`/`MetricContribution` 或分数；已有模型报告保持不变。这样可避免用户把固定规则误认为模型校准结果，并确保成长分数可追溯到模型决策。
- vNext 原则归因也遵循同一不变量：本地关键词/片段匹配只能提供候选材料；没有用户明确设置 `quest.trainingPrincipleId` 时，不自动选择训练原则，也不写入持久化 `PrinciplePracticeEvidence`。只有用户选择的原则才可携带为 targeted practice evidence，验证中的语义解释仍由中央 LLM 负责。这样可避免把检索信号误报为模型或用户确认的原则判断。
- vNext 的单次成长结算也不再由固定本地规则生成。结果校准模型只在有充分证据时返回 0–3 条结构化结算证据；本地仅核验类型、数量及当前 Quest/Verification 引用后事务写入。模型没有给出证据时，结算仍保留原判断、实际结果和判断更新，但不展示伪造的“新增成长证据”。
- 教练追问后的自然语言回答也已进入中心决策路径：`reviewCoachAnswer` 只携带当前事项的已确认卡片、已回答问题和上一步证据缺口；模型返回准备度、下一步、可见反馈及来源引用。本地不再把回答套入模板后判定“已补足”，只处理请求取消、事项切换、引用校验与用户明确选择“带着缺口继续”。
- 本地代码仍保留资格、同意、频率/冷却、安全边界、证据引用和事务提交等客观工作。原则和模式只作为候选材料交给中心 LLM 最终选择；缺少 API Key 时 vNext 只保留可重试状态，fallback 仅用于显式测试/预览。

## 本轮已执行的小步

历史页面现在在显示成长数量、判断是否存在证据以及渲染列表时都使用同一套“来源证据最新版本”归一化。这样不会改变成长计算，只消除修订记录在 UI 中的重复。对应回归测试覆盖旧版本与新版本并存的情况。

## 下一小步

本轮已把“候选材料”和“最终判断”分开：

1. 配置 API Key 的 Verification 请求失败时只进入可重试状态，不写入本地伪校准或伪结算。
2. 原则候选通过结构化 PromptContext 交给中心 LLM 最终选择，保留现有证据引用和质量门；没有必要为每个静态候选再增加一次模型请求。
3. 支线邀请继续由中心 LLM 决定是否出现、内容和奖励；通知、独立经验和非惩罚性连续记录由用户同意和本地事务负责。
4. 回答复盘请求进行中时不把本地模板结果显示为判断；用户可明确选择带着缺口继续，该选择会被保留为用户授权而不是模型“已就绪”的替代结论。响应必须同时匹配当前事项和回答指纹，跨事项引用会被拒绝。

Provider Profile、账号、同步、市场、排行榜和新的评分体系继续冻结；真实体验仍在闭环可靠性验收之后开始。
