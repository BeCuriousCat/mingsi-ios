# 明思支线邀请实验

状态：已接入 Today、Settings、LLM 决策、可选通知与正向经验账本。  
更新：2026-08-15

## 产品边界

“生活奇遇”是明思的偶然层：在主动的思考主线之外，偶尔让用户遇到一件可以错过的小事。它更像去看电影的路上遇到一个彩蛋，而不是另一张待办；它可以带来关系、好奇、兴趣、创造、活力和自我照料，但不把这些变成需要证明的目标。

它与现有 `Quest` 明确不同：`Quest` 是围绕一个判断的验证行动；生活奇遇是模型偶尔提出、用户自行决定是否去看看、留到下次或自然错过的可选体验。系统可在后台记录正向生活经历，但不会因跳过、拒绝、暂存或未发生而扣分，也不会将分数、连续天数或完成标准呈现为参与动机。

参考来源是用户提供的“地球 online 支线任务”图文。内置文案为重新编写的原创素材，不复制原图文的具体表述或视觉素材。

## 首版内容与选择规则

- `BuiltinSideQuestCatalog` 只作为版本化参考素材库；它不再决定今天是否出题，也不直接决定展示哪一条。
- 支线邀请默认处于可观察状态，用户仍可随时关闭类别或全部邀请；它不是每日义务。
- `SideQuestAIService` 每个允许的计划日调用一次 LLM，由 LLM 决定 `offer` 或 `hold`，并生成一件轻盈的生活奇遇。奇遇是可以错过的偶然邀请，不是任务、训练、清单或自我优化作业；每次判断都保留 `PromptRun` 追踪 ID 和理由。
- 本地代码只负责用户同意、频率冷却、可选类别、文本安全边界、通知时间窗口、单个未决邀请和一次性结算，不能替代 LLM 做内容判断。
- 拒绝或跳过不扣分，也不会反复缠住用户；每次 LLM 计划结果按自然日持久化，避免反复调用或重复出题。
- LLM 不读取位置、联系人、日历、健康或账户原始数据。用户主动授权后，设备可将近三天步数、活动能量和睡眠时长归约为粗粒度状态 token；不上传健康样本、具体数值、地点或日历原文。关系、活力、探索类邀请必须携带相应的自主选择、身体适配和熟悉路线前置条件。
- 生活情境中的家和工作地点称呼仅保存在本机与导出中，绝不进入模型请求。模型只可看到语义地点 token，以及用户明确选择的楼层、楼梯可用性和常见转换时段；旧版未归属的 `floor_count` 会保留在本地，不能作为模型 grounding。
- 每个 `offer` 必须引用 `available_grounding_refs` 中逐字匹配的 token；本地代码只拒绝未提供地点、设施或可用性依据的提议，不生成目录替代邀请。
- 用户可以接住、留到下次或让奇遇自然错过；若愿意，也可以留下一个细节、感觉或意外。系统内部保留正向生活经历记录，但界面不以分数、连续天数或完成标准驱动参与。它们都不进入五项证据指标，也不产生负向记录。
- 用户可以临时纠正当前粗粒度情境：在家、在工作地点、在熟悉地点或暂不确定。这个选择仅保存在内存，到当天结束自动失效，不保存坐标、地点名称或系统原始数据；有效选择优先于系统的粗粒度情境。
- 已发出的 `SideQuestRun` 是当时模型判断的事实快照。之后修改情境不会重新发起当天的 LLM 请求，也不会改写邀请；下一个允许的计划日才会使用新的有效情境。
- AI 邀请可展示简短的“为什么现在推荐”，只来自 `SideQuestRun.decisionRationale` 的自然语言理由。目录 fallback、缺失理由或包含内部 grounding token 的理由不展示该区域。

## 生活奇遇探索季 v1

用户可以主动开启一个 30 天的主题探索季，填写主题并可选补充意图。它是一条可随时结束的主题弧线，不是连续打卡：没有每日任务、排行榜、漏做惩罚或对主线五项指标的影响。`SideQuestExplorationSeason` 只记录接下、完成和跳过的邀请数；每一条 `SideQuestRun` 可选关联到当时仍处于 active 状态的探索季。

模型仍决定每个允许计划日是 `offer` 还是 `hold`，以及邀请的实际内容。本地只把已开启探索季的主题、截断后的意图、时间范围、完成/跳过统计和类别摘要传入模型，并在同一持久化事务中把新 offer 关联到 active 季。地点名称、原始日记、健康样本、日历原文和其他敏感情境不会因探索季而新增到请求中。探索季结束后，Settings 保留最近一季的完成数、跳过数、接下数和类别回顾，不调用 LLM 生成总结文案。

当 `exploration_season` 存在时，提示要求模型让 offer 与主题和意图有实际关联，并根据类别历史避免近季重复；若当前真实情境不能安全、自然地延续主题，模型返回 `hold`。这不是本地规则引擎，也不会把探索季变成必须每天完成的安排。

## 这一刻的照片留存

照片是生活奇遇的可选留存，不是完成凭证、教练证据或奖励门槛。用户在“收下这一刻”时可以不留任何内容、写一句感受、从相册选一张照片，或直接在明思内拍摄。

- 使用一个用户可见的系统相簿「明思·奇遇」，绝不为每次奇遇创建新相簿。
- 选图或拍摄确认后，原始 `PHAsset` 被加入该相簿；明思只保存 asset local identifier 与 `SideQuestRun` 的关系，不复制、压缩或上传图片字节。
- 直接拍摄先展示确认界面；用户确认后才请求照片库写入并保存原图。相册选择仅请求用户选择照片的有限访问权。
- 为显示用户主动选中的原图，应用请求最小的 Photos 读取权限；相机只在用户点“现在拍一张”时请求相机权限。拒绝任一权限不影响奇遇的文字留存或自然结束。
- 相片被用户删除、撤销访问、退出总相簿或无法再解析时，明思保留奇遇及文字记录，图片位显示“照片已不可用”，不恢复副本。
- iOS 不支持对照片库原图写入每次奇遇的自定义属性。总相簿是用户在 Photos 中可见的标记；精确的“照片属于哪次奇遇”关系仅保存在明思本地数据库。

## 已确认情境与未来 Agent Runtime

生活奇遇只可建立在用户自愿、可编辑、最小化的已确认情境上：当前持久资料只有家/工作地点的本地标签、各自可选的数值楼层与楼梯可用性，以及过渡时间、出行/运动偏好、禁用类别和简短 constraints；`familiarPlace` 仅是当前粗粒度 scene，不是持久地点资料。地点名称、地址、坐标、日历原文和健康样本不进入模型。每个 `offer` 必须有对应的 `available_grounding_refs`；`practical_place_home` / `workplace` 及其 `*_floor` / `*_stairs` 仅在当前 scene 匹配时可用，snapshot 另提供 `scene_*`、`availability_*` 和粗粒度健康 token。当前没有设施、预约、预算或熟悉路线 token，因此不能建议游泳、远距离场馆、陌生路线或其他外部依赖活动。情境不支持时，模型选择 `hold` 或只提出不依赖未知条件、低门槛且可拒绝的体验。

`CentralLLMDecisionCenter` 仍是判断唯一入口。Pi 不直接替换 iOS 本地状态机，当前不进入实现范围；只有完成 3-7 天真实体验并满足受控多轮、隐私、事务、无副作用和质量基线门槛后，才可作为未来服务端 `AgentRuntimeAdapter` 做隔离实验。完整协议、字段表、触发门槛与验收见 `docs/agent-runtime-decision.md`。

## 7 天本地试用记录

Settings 中的“生活奇遇试用记录”只在本机汇总最近 7 天的 `SideQuestPlanningRecord`、`SideQuestRun` 和 `SideQuestCorrectionEvent`。它展示并用于记录的字段是：观察窗口起止时间、模型判断次数、暂不出现数及其比例、发出数（`offered_at` 在窗口内）、接下数（状态为 `accepted`、`deferred` 或 `completed` 且 `accepted_at` 非空）、完成数（状态为 `completed`）、纠正数（`occurred_at` 在窗口内）、接下率和完成率。暂不出现率以模型判断次数为分母；接下率和完成率以发出数为分母。

界面不显示纠正备注、邀请或 prompt 内容、原始健康或系统数据、地点和日历原文，也不显示内部 grounding token。该记录只支持 vNext.1 对生活奇遇做保留、调整或移除的本地决策；它不写入五项训练指标，不改变训练分数或奖励规则。

## 验收边界

- DEBUG visual-QA fixture `MINGSI_VISUAL_QA_SIDE_QUEST_V2=1` uses an in-memory, AI-origin work-scene invitation. UI coverage checks place-scoped home/work floor and stair samples, common transition windows, the manual workplace scene menu, optional acceptance and collecting a moment. It contains no user place label and never calls a model or persistent user database.

- 只在后台正向记录用户主动收下的遇见和可选观察；拒绝、跳过、暂存、未发生都不扣分。
- 不把社交、出行或创作建议写成必须完成的命令；前置条件作为安全校验保留在本地，不以清单形式压迫用户，并允许无成本跳过。
- 到期验证仍保持 Today 的主要动作，但支线不因主事项数量被强行关闭。
- 不让本地目录或随机数替代模型判断。素材版本化且可审计，LLM 决策可回链到 `PromptRun`，本地边界仍可测试、可关闭。
- 对未来多轮能力，模型最多只能请求一次经用户逐项确认的最小补充情境；模型、Pi 或其他 runtime 不得自行执行现实操作、通知、持久化或权限请求。本地继续拥有隐私过滤、用户确认和事务权威。
