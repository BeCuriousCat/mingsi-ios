## 每次操作的外部台账

每个计划动作在点击发送前登记下一条不透明编号。原文仅用合成材料或本人允许的材料，留在私人本地位置；此公开模板保持空白。恢复页面、阅读历史和保存重试不是新的模型调用；任何实际重发都需另编号且消耗原预算，不因点击相同按钮而漏记。

| 操作编号/时间 | 会话代号/第几轮/材料ID | 当前版本/配置 | 点击与等待反馈 | 原生交易数/缺失状态 | 首份可读正文/实际界面可见 | 传输终态/保存/重开 | 完整可用/失败/取消/未定及证据ID |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

单次操作可以产生多次实际HTTP交易，不能将50个按钮动作当作50次HTTP。每次操作后对账交易总数与剩余登记预算；未知计数、预算缺失、身份变化或观测冲突时先停止后续发送。已经发生的额外交易如实保留，超限也不能裁掉。未发送动作不算HTTP、不算通过。

对照三份证据：发送前台账、App原生观测/正式保存、服务可获取的记录。单份导出不能恢复已经删除的行或所有观测写入失败；出现对不上的操作或缺失时保留unknown，不认定已收齐、也不继续假定预算足够。独立持久化写失败日志是尚未实现的增强能力，当前不能声称具备；即使以后增加，也不能替代原始操作台账和完整性核对。

## 覆盖与判定

- 至少7天、登记上限50次实际HTTP；完整可用至少48次，包含10段至少两轮交流。预先安排两轮的同会话关系，不在看到回答后挑选表现好的会话充数。失败或额外交易挤占预算时保留事实，不自动补足50次成功。
- 覆盖正常回复、同会话新条件、等待反馈、用户主动取消与恢复，以及实际出现的服务失败。取消或失败不是完整可用；不为制造慢回复或凑类别追加未登记请求。故障注入和隔离测试单独报告，不能混入真实网络成功数。
- 完整可用需联合核对回应合法、内容回应当前请求、正式保存、可读与重新找到；`returned_data`、`committed`和模型自评都不能单独判定。由AI审读时如实标注身份，不记真人获益。
- 每次等待10秒内有可辨状态，取消可操作，流结束/失败能区分。分别报告首次解析可读正文、首次界面可见正文、完整回应的时间定义、样本数和p50/p95；保存和传输终态分开，失败/取消及缺失不从报告消失。
- [离线汇总](mingsi-network-summary.md)只辅助对账，不判G3通过。配置未知的记录不生成同服务延迟分位数；汇总保留全部失败及缺失，版本不同不拼接。
